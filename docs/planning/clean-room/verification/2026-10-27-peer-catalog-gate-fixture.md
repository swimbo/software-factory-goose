# Unix peer and task catalog fixture

The disposable replay harness now exercises a fixture-only Unix-socket gate using macOS `getpeereid` on each accepted connection. A server-owned fixed catalog binds call IDs and request bytes to a real disposable `ClaimLeaseJournal` task, immutable spec and exact worker lease. Caller-supplied UID/task fields, changed payloads and unknown IDs are rejected; a spoofed UID header does not affect the actual kernel peer identity. A second socket configured with a deliberately different expected UID rejects the same real peer. Ten simultaneous authorized calls to one catalog entry result in one synthetic provider request. Once that claim is completed, a later catalog request is denied without another provider call.

The fixture also injects two revocation races. When the claim is revoked between two status reads, the second read detects it and denies the request. **When the claim is revoked after the final status read and before `begin`, the fixture still contacts the synthetic provider.** The second read is not atomic authorization. This is a confirmed blocker, not a passed production gate. Atomic admission needs claim validity and inference reservation/dispatch fencing under a single authority, or an equivalent verified protocol, plus a defined way to handle revocation of an already admitted external call. The current inference object also does not itself bind the actual task or lease token.

The full disposable Restate/PostgreSQL replay passed after adding the explicit late-revocation canary. Earlier attempts exposed three fixture issues: the initial Unix socket path exceeded macOS's length limit, the additional claim changed a prior global outbox count, and the default socket backlog rejected some concurrent clients. The fixture now uses a private temporary workspace directory with short socket names, runs after that count check, and uses a bounded larger backlog.

This is a same-UID fixture: the mismatched expected UID test does not create or test a second OS account. Its socket mode and temporary directory are fixture-local; it does not establish production socket ownership, ACLs, trusted catalog provisioning, actual Goose routing, Bifrost credentials or a separate identity. The earlier TCP egress canary and this Unix peer test are separate experiments, not one integrated deployed boundary. No provider, worker or production service was activated.
