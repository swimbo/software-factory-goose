# G03 authenticated holdout transfer component

Date: 2026-10-27. Unregistered library adapter only. No users, groups, standing paths, listeners or runtime services were provisioned or activated.

`ManifestServer` preloads one digest-selected immutable manifest through `ProtectedHoldoutStore`, retaining its authenticated store/evaluator/generator configuration. `ManifestClient` receives only the independently pinned expected digest and trusted principal configuration; it has no store path or file-reader handle. Production construction checks actual effective UID against the relevant role and requires all three configured principals to be distinct and nonroot. Each exchange rechecks that role, takes ownership of its Unix stream and checks the actual connection's kernel peer credentials before sending or reading protocol bytes. No request-supplied identity is accepted.

Protocol: one version1 JSON request with only `version` and `digest`, capped at256bytes, followed by exactly one raw manifest response capped at128KiB. Frames have a four-byte big-endian length; zero/oversized frames fail before allocating the body. One10ms–5s total network deadline covers headers, partial bodies and writes. The server refuses requests for every digest except the selected manifest. The client verifies exact SHA-256 and strict schema and requires end-of-stream after the frame, refusing trailing bytes and never-ending responses. Failure closes the connection and yields only `holdout transfer unavailable`. Source bytes remain private crate data with no public Debug/Serialize accessor. Generator feedback remains the collector's coarse status and opaque IDs.

Test-first evidence: new protocol tests failed before the API existed. After implementation, ten focused tests passed using real local Unix streams and kernel credentials. They cover exact-byte digest roundtrip; evaluator/store peer mismatch with zero bytes disclosed; body-forged UID, wrong digest and malformed JSON; oversized/truncated request and response frames; invalid response digest/schema; stalled headers/bodies; trailing response bytes and missing end-of-stream; invalid role/duplicate/root UID configuration, bad deadlines/digests; and a real protected-store reader plus real listener whose public server rejects the same-owner peer. `cargo clippy -p evaluator --all-targets -- -D warnings` passed.

Positive transport tests intentionally call private protocol functions with the actual current UID on both ends. Production constructors have no such bypass. Other fixture UID values are synthetic; no account existence, separate-account success, deployed generator denial or R1 runtime isolation has been established. The real-listener test verifies a public refusal, not successful deployment.

Regression result: `cargo test -p evaluator` passed all54 tests (19 library,9 exact-revision,8 prefilter,8 runner,10 protected-store); no tests ignored. This includes real Seatbelt scenario execution and the prior protected-store filesystem fixtures. `git diff --check` passed.

Remaining integration: protect socket paths and descriptors, provision/check actual principals, bound concurrent connections, authenticate authoritative task/manifest selection, connect fetched manifests to the evaluator lifecycle, persist trustworthy results, and demonstrate cross-UID denial plus independent containment/recovery. This component assumes the kernel and configured local principals are trusted; it cannot prevent root compromise or a trusted evaluator intentionally delegating an authenticated descriptor. The server's manifest is a fixed in-memory snapshot; revocation requires externally closing/dropping that instance. Initial synchronous filesystem loading is outside the network deadline. No worker/generator endpoint returns manifest contents, and no listener is registered by this change.
