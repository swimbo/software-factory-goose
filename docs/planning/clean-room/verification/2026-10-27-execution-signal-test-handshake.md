# Execution cancellation test synchronization

The combined run recorded `descendant survived signal 2` in `2026-10-27-tests-resume5-final.log`. The former fixture let the descendant write its marker one second after startup, while the test waited for a different file and then sent SIGINT. Under scheduling delay the marker could already exist before the signal. The retained failure log does not record marker ordering, so this race is a plausible cause rather than a confirmed explanation; a real cleanup failure is not ruled out by that log. Six isolated repeats of the original test passed.

The revised test waits for the descendant's own readiness file and requires its marker to be absent before acting. An unsignalled positive control releases the descendant and verifies the marker appears. In the SIGTERM and SIGINT cases, the test signals only its live owned execution process, waits for its response, then creates the release file and observes for two seconds that the marker remains absent. The disposable descendant's polling is bounded; its stdout and stderr are redirected so a surviving descendant does not hold the response pipes open. Two focused runs and the full six-test `tool_request` suite passed; strict execution Clippy passed.

This improves the test's falsifiability and removes the specific marker-before-signal ambiguity. It does not prove that the historical failure was a test artifact, that all signal races are safe, or that escaped descendants are stopped. The independently identified ignored group-signal error remains open in [execution signal-failure evidence](2026-10-27-execution-group-signal-failure.md).
