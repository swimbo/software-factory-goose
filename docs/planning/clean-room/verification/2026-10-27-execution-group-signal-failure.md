# Execution supervisor signal failure

`execution`'s local shell supervisor invokes `kill(-pgid, SIGKILL)` while its sole-waited group leader remains unreaped, but currently ignores the syscall result before waiting. A rejected signal therefore cannot be treated as proof that the complete group stopped. The supervisor is not a production isolation boundary; `run_goose` remains disabled.

A test-first prototype preserved the child handle and propagated failed signals. The explicit injected `EPERM` case then retained ownership and could retry. However, on this macOS host the full execution tests also reported `EPERM` when normal short-lived group leaders had already exited: five existing normal/timeout tests failed. The prototype was reverted; accepting `EPERM` as success would merely hide the original problem. The failed run is retained in `2026-10-27-execution-signal-prototype-failed.log`. A safe implementation needs an owned, live group leader or another independently verified lifecycle mechanism and negative tests for signal failure, PID reuse, descendants and cancellation. Neither the test nor the current supervisor establishes that escaped descendants stop.
