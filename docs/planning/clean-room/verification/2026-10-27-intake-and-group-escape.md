# Intake restart and process-group escape fixtures

The disposable native Restate/Postgres fixture now registers the otherwise unregistered `IntakeJournal` and sends ten concurrent identical submissions to one key. All return the same stored record; changed intent under that key returns 409. A separate race between conflicting first submissions admits exactly one and rejects the other. The same exact retry, conflict and inspect results, including the race winner, survive both graceful restart and SIGKILL after acknowledgement. See `2026-10-27-intake-restate-runtime.log`; the fixture also ran its existing worker, budget, approval and Git checks. The configured principal is synthetic, the endpoint is loopback, and no public or authenticated intake adapter, in-flight crash proof or production deployment is established.

The narrow private Unix intake router passed four socket/mocked-backend tests for peer binding, duplicate and conflicting requests, invalid/oversized requests and foreign-record refusal. Separately, a real `UnixIntakeBackend` connected through the same-UID disposable proxy to Restate. After the proxy discarded a response that had begun, inspect recovered the committed record, exact retry returned it unchanged and conflicting reuse was rejected. The first fixture run failed because its socket pair's peer was dropped before credential lookup; the preserved pre-fix log records this, and the corrected run passed. The router and real backend were not exercised together across distinct accounts. The backend's configured principal must match the registered journal; post-response checks cannot undo a misconfigured first write. Private ingress and authoritative principal configuration remain activation gates.

`python3 clean-room/tests/fixtures/process_group_escape.py` passed on the local macOS host. It starts two directly owned children in a fresh process group; the second creates a new session with `setsid`. Killing the original group terminates its leader while the escaped child remains alive. The test directly kills and reaps that still-owned child in `finally`, with bounded waits; it never signals a reaped or externally supplied PID. This falsifies treating group termination as complete family containment. It is not a test of a privileged supervisor, sandbox or VM and does not stop arbitrary descendants.
