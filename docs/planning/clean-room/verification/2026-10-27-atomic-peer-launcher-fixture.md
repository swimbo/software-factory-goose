# Unix peer launcher with same-object admission

The disposable replay harness now connects the existing macOS `getpeereid` Unix-socket fixture pattern to the unregistered `AtomicInferenceFixture` and a synthetic loopback provider. A fixture-owned catalog fixes each task, lease token and attempt, call ID, exact request bytes and digest, model, review digest, reservation amount and provider endpoint. The caller supplies only a catalog ID, matching task name and synthetic payload; the begin response and lease token stay inside the gate.

The full disposable Restate/PostgreSQL replay passed twice. The actual same-UID peer was accepted; a socket configured for a different expected UID rejected that same peer despite a spoofed UID header. Wrong task, unknown ID, changed payload and caller-supplied UID, token, attempt, amount, digests, provider or begin fields were rejected before the provider. Ten concurrent calls for the same entry produced exactly one provider request. A synthetic provider that accepted and dropped its reply saw one request; retry was denied. At a deterministic barrier before `begin`, revocation won and no provider request followed. At a barrier after successful `begin`, revocation did not retract that admission and the synthetic provider was called once. All call stages and replay refusals survived graceful and SIGKILL Restate restarts; the SIGKILL did not interrupt an in-flight journal operation.

A later combined replay exposed a wrong-peer fixture transport race: the gate could reject and close before the HTTP client finished writing, raising `BrokenPipeError` instead of receiving 403. The test now accepts only broken-pipe or connection-reset on that negative path, and only after the server independently records the actual kernel UID and its mismatch with the configured UID. Authorized calls use the original strict transport; unexpected success and unrelated transport errors remain failures. The complete replay and two focused transport controls passed after the correction, with no provider call on the denied path.

This integration is a fixture, not deployment authorization. The lease is created directly inside the fresh atomic fixture namespace, not obtained from the existing `ClaimLeaseJournal`; no migration or exclusive cutover exists. The fixed catalog is constructed by the test, not a trusted production task authority. The positive and mismatched-policy tests use the same OS UID, not two provisioned accounts. The socket has no verified production lifecycle or ACLs. The gate is trusted not to reuse a successful begin or bypass the journal, and this test does not combine it with the separate sandbox egress canary. Actual Goose, Bifrost, credentials, daily budgets, billing and cancellation of already admitted sends remain unverified. No production route or live provider was activated.
