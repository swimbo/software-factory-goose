# Operator identity lookup deadline

The macOS operator socket binder uses fixed `/usr/bin/id` and local account/group commands before opening an operator ingress. Its prior reader thread could block after the direct child had exited if another process retained the stdout pipe, bypassing the three-second limit. The test-first fixture ran a harmless shell child that exited with a five-second pipe-holder; it failed after 5.01 seconds because lookup incorrectly returned success.

The helper now reads the pipe nonblocking, checks direct-child status and a single deadline, bounds output to 16,384 bytes, and refuses inherited SIGCHLD auto-reaping before spawning. Cleanup signals only a direct child that has not already been observed reaped. A synthetic retained pipe now returns an error at the three-second deadline; an isolated subprocess test verifies auto-reaping is refused before launch. `cargo test --offline --locked -p control-plane --all-features --lib operator_transport::tests::` passed 7 tests before the final additional auto-reaping case; the final `cargo test --offline --locked -p control-plane --all-features --lib operator_transport::tests::identity_lookup` passed both deadline and auto-reaping tests. `cargo clippy --offline --locked -p control-plane --all-targets --all-features -- -D warnings` passed after the final change.

This bounds the helper's wait and avoids signaling a child already observed reaped; it is not descendant containment. Concurrent process-wide changes to SIGCHLD remain unsupported. No accounts, existing services, or credentials were changed. The fixture runs as the current account and does not verify deployed operator provisioning, private ingress or independent process containment.
