# Durable intake to qualified task handoff audit — 2026-10-27

The durable intake cannot safely schedule work yet. `IntakeJournal.submit` only creates an immutable `AwaitingQualification` record; `inspect` reads that record and neither produces a qualification nor schedules a task. The private adapter is unregistered and binds a configured principal to a kernel peer, but it has no qualified-task operation. Its scope is admission, not authorization to execute.

The only implemented qualifier is a pure function taking supplied numeric `IntentFeatures`. The diagnostic HTTP endpoint chooses provisional greenfield factor defaults and checks a caller-selected local `AGENTS.md`; its result is explicitly diagnostic and is not projected as an authoritative decision. `pipeline::decompose` creates a fixed demonstration DAG from arbitrary spec text. Neither supplies a verified executable spec or revision-scoped evidence. `WorkerQueueJournal.schedule` accepts an already-supplied package ID and repository/base revision, initializes a claim, and does not receive or independently verify intake, qualification, dependencies, target ref, or task provenance. The queue itself is unregistered and its documentation requires private scheduler authorization before activation.

An actual handoff needs all of the following connected and tested before scheduling can be enabled:

1. A trusted repository registry must resolve the intake's logical repository and full base revision to a specific authorized repository and object; the caller's text is not that proof. Revision-scoped knowledge and dependency evidence must come from that same immutable revision.
2. A versioned qualifier specification must define how verified executable spec, evidence, artifact/trace metadata, environment fingerprint, and missing or stale evidence yield bounded factors and fatal flags. The existing formula has no grounded evidence extractor or calibration. Ambiguity must prevent autonomous dispatch rather than substitute the diagnostic defaults.
3. One durable task authority must bind the immutable intake ID and payload, repository/ref/base, qualifier version and evidence, resulting lane, spec and DAG to the exact scheduled package IDs and dependencies. It must serialize decisions with scheduling, preserve idempotent replay, and have a defined recovery/outbox path. An independent queue request carrying caller-supplied fields is not a substitute.
4. Private authenticated scheduler ingress must make the authority the sole source of schedule requests, and the execution-side lease must still check worker identity and current lease validity. A human-lane decision must not be converted into autonomous work by an untrusted caller.

The required O3 follow-on specification and runtime producers are not present in the checked planning artifacts. No synthetic authority, new public endpoint, or queue connection was introduced by this audit. The separate local operator account and action-bound approval decision remains as previously chosen; it does not itself resolve qualification or repository authority. The full INT-LOOP and G-07 remain open.
