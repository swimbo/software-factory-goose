# Root stop backend: V2 build, installation and native canary

The reviewed V2 root stop backend is installed on the NUC and passed a scoped native canary. It is **not a production brake acceptance**: the nonroot frontend remains uninstalled and its draft incorrectly treats operator UID 1000 as the strict `BrakePolicy` brake peer. A separate explicitly named policy is being debated; do not deploy that draft or omit the operator from the old policy's exclusion list.

The isolated NUC build used a private Cargo registry copy, separate target and two jobs. V2 watchdog library tests passed 20/20, including the regression that holds the launch lock while acquiring the independent stop lock; all-target strict Clippy passed. The V2 binary SHA-256 is `99236f262d181442e395a9f706e99856027fab7f069bcb6fefb6950b0c324443`. The reviewed V1-to-V2 installation and its durable receipt were performed through owned bridge `/tmp/sfactory-identity-admin-cdcn79d_`, without activating a production frontend. V1 was backed up rather than discarded. The old native fixture was separately cleaned through `/tmp/sfactory-identity-admin-xhzbv15l` before the upgrade; its expired sleeper was not counted as a positive test.

The fresh actual V2 canary ran through owned bridge `/tmp/sfactory-identity-admin-vsiyghwv`. It launched an isolated UID 2001 native worker and a setsid descendant into a unique owned systemd slice. It verified the worker could not write cgroup migration or freeze controls. A UID 2000 peer with socket group access was denied without closing admission; a UID 2003 peer then requested stop while the test held the target's **launch** lock. The root service's successful ExecStartPre confirmed its mount namespace could not connect to the Docker socket. While the launch lock remained held, the root backend returned closed/frozen/empty, and the canary independently observed the same cgroup inode frozen and unpopulated. It stopped the exact owned unit and slice and test-activated root socket/service, then checked the retained original Docker object and existing services. The protected result retains `engine_reconciled=false`: the native fixture had no pending Docker operation.

Target `01M65DMY16BR2CQH9H8JKXC4TB` has a retained root-owned catalogue at `/etc/software-factory-goose/tasks/01M65DMY16BR2CQH9H8JKXC4TB.json`, permanent closure at `/var/lib/software-factory-goose/stop/01M65DMY16BR2CQH9H8JKXC4TB.closed`, and canary receipt `/var/lib/software-factory-goose/stop/01M65DMY16BR2CQH9H8JKXC4TB.canary-receipt.json`. The receipt records `launch_lock_held_during_stop=true`, `kernel_stop_verified=true`, `slice_removed=true`, and `engine_reconciled=false`. A separate fixed read-only receipt inventory ran through `/tmp/sfactory-identity-admin-h5mpusst`. Bridge manifests and results remain in those owned private directories.

The root catalogue binds schema 1, target and task IDs, generation equal to target, boot ID and cgroup device/inode. The cgroup path is derived as `sfactory<lowercase-generation-ULID>.slice`; callers cannot select a path or PID. Stop fsyncs `<ULID>.closed` before taking `<ULID>.stop.lock`, then validates the cgroup2 descriptor, freezes and kills its recursive subtree, and observes same-inode frozen/empty. The separate launch `<ULID>.lock` cannot block this stop path. A future launcher must check permanent closure before and after effects and must never recreate a generation cgroup; this has not yet been integrated or proven. A kernel-stopped result does not establish engine reconciliation. Status is a protected historical observation, not a claim that the subtree remains empty.

The native canary does not prove container escape prevention, delayed Docker create/start reconciliation, real Docker-daemon failure, owner loss, helper restart, host reboot or power-loss recovery. It does not validate the authorized frontend or the authoritative claim/lease-to-launch binding, which is not yet implemented. Retain unknown effects and previous fences; do not infer production readiness from this canary.
