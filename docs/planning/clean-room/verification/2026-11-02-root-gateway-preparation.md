# Root gateway preparation checkpoint

The private `_prepare_gateway` path validates the current grant and guard, records a one-use spawn intent, passes the pinned sealed helper, bound socket, executable descriptor and pipes to a credential-free gateway UID, waits for helper readiness, closes Root's socket copy, calls `_attach_gateway`, and records the gate and child identity. It returns the still-closed gate to its caller; it does not authorize release, inference or production admission. On preparation failure it closes the gate and kills and joins the child. The caller must fence and reconcile any attempt with an unknown result; cleanup after socket handoff remains unqualified.

Two component tests cover spawn ordering, descriptor and privilege settings, closed-gate preparation and failure before readiness. A network-disabled Linux fixture exercised the real helper process and Root spawn method: closing the returned gate prevented execution, and a synthetic attachment refusal killed and joined the child. The fixture mocked Root's grant, guard and attachment, and did not test actual migration or a production Bifrost process.
