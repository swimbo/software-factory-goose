# Idempotent reservation object: disposable Restate fixture

An unregistered `IdempotentBudgetCounter` prototype owns a **new, separate Restate object namespace**. Its single retained state binds the object key as budget scope, validates a canonical ULID and nonzero integer microUSD amount, and records both admitted and denied outcomes. Exact retries return their original outcome; the same ID with a different amount returns 409. A maximum of 256 records is retained without eviction; capacity exhaustion rejects new IDs while preserving old retries. The entire retained history and total are checked before each mutation. No reset or raise operation exists.

The module's three focused tests passed after an initial missing-implementation compile failure, and strict all-feature/all-target control-plane Clippy passed. The rebuilt disposable Restate/PostgreSQL replay fixture passed: a response was discarded after beginning, the same ID was retried, and the remaining 500,000 microUSD was admitted, proving a single 250,000 reservation. A conflicting amount was rejected. Ten concurrent calls with one ID all returned the same admission, and the remaining 650,000 microUSD could still be reserved; a further microUSD was denied. Admitted and denied retries persisted through graceful and SIGKILL restarts. The SIGKILL occurred after acknowledged operations, not in-flight during a mutation.

This does **not** fix the existing `GatewayClient` or `BudgetCounter`: they use the original namespace and can still double-reserve after a lost acknowledgement. A separate namespace cannot safely be run as a second spending authority for an existing unit. Old ledger inventory and an exclusive, verified migration or retirement protocol are absent. Before any use, a trusted caller must durably bind one reservation ID to each logical inference and exact amount before dispatch, protect and authenticate budget scope and ingress, and prevent all old/alternate ledger and inference paths. Cross-scope global identity, daily cap, provider response reconciliation, retention archival, private deployment, and crash injection during the state transition remain unproved. No production handler was registered; only the disposable fixture binds this object.
