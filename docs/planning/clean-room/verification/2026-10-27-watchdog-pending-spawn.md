# Watchdog pending-spawn brake fixture

The subsequent per-family lock and bounded concurrency changes are recorded in [family isolation verification](2026-10-27-watchdog-family-isolation.md).

The previous blocked-spawn probe showed that a child stalled in `pre_exec` kept the registry mutex across `Command::spawn`, preventing stop from acquiring it. The registry now reserves a bounded pending launch while holding the lock and spawns outside it. Stop closes admission, signals registered owned groups, waits up to the existing two-second group-cleanup deadline, and returns `pending_launches` with aggregate termination fields false while any launch is unresolved. A child returned after stop is retained under the same sole-reaper ownership, stopped, and rejected as a successful launch. Expiry during spawn also closes the family and rejects the late launch.

On this macOS arm64 host, `cargo test -p watchdog --all-features --locked --offline` passed 20 tests, including a race between launch and stop and a deadline expiring during stalled child setup. `cargo clippy -p watchdog --all-targets --all-features --locked --offline -- -D warnings` passed. `cargo run -p watchdog --example blocked_spawn_probe --locked --offline` passed: an existing owned sleep group was reaped, stop returned with one pending launch and false aggregate termination and signal status, a further launch was refused, and after releasing the blocked setup its late child was stopped and reaped. An intermediate version returned before reaping the existing group and failed this canary; the final version waits for registered groups up to the existing deadline.

The returned-child path retains and attempts to stop an owned child when reacquiring its family lock detects poison, or when the registry index is poisoned. A deterministic test intentionally poisons the family lock while a pending shell starts a descendant, then verifies that the returned leader is reaped and the inherited output pipe closes. A separate test poisons the index while a child is pending and checks that the returned child is quarantined and reaped. A poisoned family remains unavailable; a poisoned index makes ordinary lookup unavailable. Registry drop examines poisoned records rather than skipping them, but cleanup is best effort and does not constitute recovery or a containment guarantee.

This is a same-UID disposable fixture, not a containment or complete independent-brake proof. A child stalled before `spawn` returns has no registered handle and is not stopped by this response; after release it can run briefly before the parent receives and stops it. Escaped descendants, cross-UID authority, owner crash, registry poisoning, blocked kernel operations, and independently verifiable VM teardown remain open. The result must remain unresolved until all pending launches and groups are accounted for; no numeric PID is persisted or signaled after its owned child is reaped.
