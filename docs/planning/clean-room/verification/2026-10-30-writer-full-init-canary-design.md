# Synthetic full writer initialization canary — design for review

A separate fresh random ULID generation and task must be recorded in a root-only durable intent before effects. This is synthetic test authority only: it cannot reserve a real journal claim, mutate an existing catalog, or authorize a model call. Collision checks must cover the fixed generation paths, service/socket names, cgroup and Docker labels. Preserve every intent and resource on an ambiguous effect.

1. Establish a fresh systemd worker slice and harmless bounded anchor; bind a new root task catalog to its boot, exact cgroup device and inode. Mint a synthetic deadline-only grant and arm the existing independent root native stop timer before the first Docker create. Time and monotonic expiry must match the writer's required deadline record. The timer closes and freezes/kills the exact cgroup even if the canary controller dies.
2. Create the exact fixed writer image in that slice with UID/GID 2001, network none, read-only root, no capabilities, no-new-privileges and the three fixed owned handoff binds. Persist create intent before Docker create, full ID and validated Docker inspect receipt before start, then start once; ambiguity retains identity and prohibits retry. Confirm kernel process UID, seccomp, capabilities and cgroup ancestry. Do not publish a writer input or cause the writer to modify candidate data.
3. Create root-only synthetic launch catalog, consumed binding, scope, task and writer seal whose hashes, mount identities, IDs, deadline and scope conform to the actual installed writer module. The provider binding points to the already pinned trusted Bifrost container only for `docker inspect` and network namespace metadata. It does not open the factory credential, make HTTP calls or choose a model. Mark all records synthetic and keep them distinct from the production catalog/journal.
4. Create a new root-owned systemd socket and the exact installed writer service under UID 0, capability-empty and its existing sandbox. The listener must be passed by systemd FD activation. A separately bounded UID 2000 client sends only `{"op":"guard"}` and expects one valid guard response from the actual broker. This forces `HostAuthority.verify`, including deadline, provider metadata, fixed writer Docker inspection and kernel process protection, after real main initialization. No `write_files` request is sent.
5. Close admission and invoke the independent native kernel stop. Verify the exact cgroup inode frozen and empty and the writer service terminal with no pending jobs before stopping its socket. Inspect and remove only the recorded exact full container ID after known terminal outcome; verify it is absent and the cgroup is still empty. Retain the frozen slice, intent and receipts for audit; no generic prune, force remove, or cleanup by name. Unknown create/start/stop, missing ID, active broker or failed cleanup quarantines state and produces no success receipt.

Negative controls must deny an altered cgroup inode or non-cgroup filesystem, expired deadline, wrong listener peer and unavailable writer. The canary is not proof of journal-authorized launch, real provider delivery, host/daemon-loss recovery, or candidate evaluation. The exact ordering and cleanup authority need source and plan review before any run.
