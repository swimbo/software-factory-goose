# Same-object durable promotion decision

Date: 2026-10-27. Unregistered production library component; registered only in the disposable loopback SDK fixture. No Git mutation or external action executor exists in this component.

`PromotionDecisionJournal` is keyed by task and owns one persisted `promotion` state value containing its eligibility generation, normalized eligible action, change receipts, approval records and decisions. Exclusive `ObjectContext` handlers serialize publication, invalidation, issuance and consumption. Consumption compares the approval's generation and exact action with the current eligible action, checks operator/audience/expiry/presentation, and places both the consumed approval and immutable decision in that same state value with one `ctx.set`. There is no call to another journal, local lock or external executor between these checks and that write. Shared lookup/inspection reads recover the stored result.

The authority scope is deliberately limited: this object owns **its publication/invalidation state**, not the existing `ClaimLeaseJournal` or every current task-state writer. `EligibilityPublication::from_authoritative` applies the existing `prepare_promotion` checks to a server-held snapshot, actual wall evidence and prefilter report, binds the next generation, and emits a normalized action/evidence digest. The digest is a summary, not a signed execution transcript. Deserializing publication JSON proves no authority. Activation requires separately authenticated trusted-source publication and routing every eligibility-changing writer through this object. An operator or generator must never have publication privileges. Constructor identity configuration alone authenticates no request.

Transitions and bounds:

- A trusted publication or invalidation uses a canonical request ID and expected generation. A new change increments generation; stale generation and changed reuse fail. Exact historical retries return their original receipt without changing current state. Invalidation removes current eligibility and current decision selection while retaining historical decisions.
- Issuance derives an action from current object state and the operator's reason. Its canonical request ID recovers the same nonce/lifetime/result after a lost response, including after consumption or later generations. Nonces and time are obtained through `ctx.run`, stable during Restate replay.
- Consumption refuses stale generations, absent eligibility, changed bindings, wrong operator/audience, expiry and replay. Only one decision can succeed per generation, even when multiple approvals exist. All failed pure transitions leave state unchanged.
- Stored state retains at most64 change receipts and64 approvals; publication stops at63 changes, reserving the final slot for invalidating live eligibility. Capacity exhaustion never evicts records or resets idempotency. Canonical action/input fields retain existing explicit length limits. These are retained-state bounds; production ingress still needs request/concurrency limits and role enforcement.
- Decisions retain exact action, nonce, generation and consumption time with `execution: NotRequested`. They are inspection data, not bearer permissions or evidence that Git ran. Historical lookup remains available after invalidation.
