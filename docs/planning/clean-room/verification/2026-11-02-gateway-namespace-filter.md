# Inherited gateway namespace restrictions

The pinned pre-exec filter now denies `unshare` and `setns`, and rejects classic `clone` calls carrying namespace flags on x86-64 and ARM64. `clone3` returns ENOSYS because classic seccomp cannot inspect its pointed-to flags; ordinary callers can fall back to the permitted classic clone path. The filter is installed after Root's namespace bootstrap and before the gateway release gate. The Root helper digest is updated; both harness profiles already bind these sources.

The strengthened [native target](../../../../clean-room/tests/fixtures/harness_gateway_exec_target.go) first runs unfiltered controls: no-op unshare succeeds, setns with an invalid descriptor returns EBADF, invalid namespace-clone/thread combinations return EINVAL without creating children, and clone3 with a null argument returns EINVAL. The filtered target and its exec child instead observe the expected EPERM namespace denials and ENOSYS clone3 result. Normal Go startup, child exec, local TCP and Unix listener activation still complete. The existing joined Root preparation/real attachment/release/fence fixture passed with this target on the x86-64 NUC. See the [receipt](2026-11-02-gateway-namespace-filter.json).

Before implementation, the new target failed with exit 25 under the original filter. The updated helper passed. An isolated mutation that zeroed only the classic clone namespace mask also produced exit 25, establishing that the clone restriction is detected independently of the unshare/setns checks. No shared source was mutated for that control. The exact live child was killed and joined; independent observations confirmed its identity, disposable attempt/controller cgroups and containers absent.

Separate fresh network-disabled rehearsals passed the actual Bifrost handler and the actual durable wallet/Root scope/broker/capture join under this same filter digest. Their filter markers and installed helper hashes were checked. Routes, provider, authorizer and production Root construction remain synthetic. The configured Python harness ran 278 tests: 271 passed and seven skipped; Ruff passed. The ARM64 target cross-compiled, but the ARM64 filter has not run natively. Five local source-review lenses completed without actionable findings. The cross-model route was unavailable before egress; a separate local adversarial reviewer covered that lens.

This restricts namespace changes by the filtered process and descendants. It does not establish exclusive namespace membership, prevent a trusted privileged outside process from joining, qualify production credential/descriptor custody, or authorize handed-socket cleanup. Production bootstrap, egress fencing and the complete failure lifecycle remain open. No candidate activation or paid inference occurred; live attempts remain 0/120 and the existing $5/UTC-day and $0.75/permanent-task caps remain binding.
