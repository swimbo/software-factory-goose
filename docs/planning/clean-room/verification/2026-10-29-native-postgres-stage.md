# NUC native PostgreSQL staging

On 2026-10-29, built PostgreSQL 17.11 and pgvector 0.8.7 as the ordinary NUC user in `/tmp/sfactory-pg1711-build.vfNv9w4h`; no host package or service was installed or changed. PostgreSQL source came from the [official 17.11 source directory](https://ftp.postgresql.org/pub/source/v17.11/), and the official archive SHA-256 check passed: `dd27f2b3c59e73ed14aa3324901242bf69a032a6347805f274e6260322d42979`. [pgvector's upstream](https://github.com/pgvector/pgvector) tag `v0.8.7` resolved to commit `f37c13f68b57d2c3472b2214fbcff699d6d34876`. Debian bison, flex and m4 were downloaded and extracted into this task directory, not installed. Configure used `--without-readline --without-zlib --without-icu` and prefix `/usr/local/libexec/software-factory-goose/postgresql17`; build and staging ran at nice 10 with two jobs. Build and install logs are in that task directory.

Staged tree is `stage/usr/local/libexec/software-factory-goose/postgresql17`, 35 MiB. `staged-tree.json` records 1,771 directory, file and symlink entries with modes, file sizes and hashes and link targets; its SHA-256 is `39216b7ac1e082074b9e6098e5a3c94a0d706a1910cc302b9df0eddd4d9d23e5`. `staged-files.sha256` records regular-file hashes (manifest SHA-256 `cecdd60a14faca0d9d795839bbb8eec4eb266d193f127fac4f569008ca6d38b7`). These are task-user-writable artifacts: an installer must revalidate against a root-pinned reviewed manifest, reject extras and path replacement, and refuse an occupied destination before copying. At the initial staging checkpoint, neither root copy nor activation had occurred; the later root-copy result follows below.

A new disposable database in `/tmp` ran only on its private Unix socket; `CREATE EXTENSION vector` succeeded and `pg_extension` reported `0.8.7`. The server was stopped and the disposable data removed. Log: `smoke.log` in the build root. Staged clients need `LD_LIBRARY_PATH` to the staged `lib` directory; a deployed service must use its fixed installed `lib` path. This smoke test does not prove private-network deployment, fresh production genesis, upgrade, migration, recovery, or integration with Restate.

The installer dry run initially refused shared timezone hardlinks; 257 task-owned staged entries were normalized to independent files with unchanged bytes/modes. A subsequent unprivileged full 1,771-entry copy passed against the same pinned tree manifest into a disposable `/tmp` destination, then cleaned that copy. The root checks were mocked in this dry run. The initial five targeted tests passed on both macOS and NUC, covering create-only collision, extra source entries, changed bytes, symlinked ancestor and ACL/unknown errors. See `installer-tree-test.log` and `installer-test.log` in the build root. That dry run preceded root review and application.
