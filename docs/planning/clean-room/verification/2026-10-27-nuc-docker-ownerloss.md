# NUC Docker controller-loss integration fixture

`python3 clean-room/tests/fixtures/nuc_docker_guardian_spike.py` passed twice. It reuses the two task-owned system slices identified in [the slice spike](2026-10-27-nuc-docker-slice-spike.md); no new slice was created. The local harness transfers the existing fixture-only `docker_owner_guardian.py` and a fixed benign workload into a private temporary directory on the NUC. It uses the existing engine, the pinned local image, and fresh random labels/names. The temporary files and both test-owned containers were removed after each run.

A task-owned parent-slice anchor holds the slice hierarchy while the guardian starts its exactly labelled nonroot worker in the worker child slice. The test verifies the engine's full container ID, label, configured cgroup parent, absence of user mounts, no network, and the live container process's membership in that slice. The child verifies `setsid`, zero effective capabilities and `NoNewPrivs`, and cannot write its visible cgroup root's `cgroup.procs`. A handshake shows that it is alive after its in-container guardian has been killed and reaped. The controller is a separate owned sleep process holding the guardian pipe; the test kills and reaps that controller only after the handshake. The surviving host guardian detects EOF, closes its one-shot admission, kills and removes the exact labelled worker, verifies the engine reports it absent, repeats cleanup, and refuses readmission.

An outside observer then reads `populated 0` from the same worker slice inode (`6882200` in both runs) while the anchor remains alive. The earlier [slice spike](2026-10-27-nuc-docker-slice-spike.md) supplies the no-kill delayed-marker control. This is a real controller-pipe loss test with a synthetic controller; it is not an application-integrated launch or a production authorization path. The cgroup write negative control covers the visible cgroup root, not every possible host-cgroup migration or namespace escape.

The two root-owned slices remain as documented in the earlier note. Their task-owned container labels are absent and their `cgroup.events` both report `populated 0`. An earlier exact, empty-slice stop was denied because interactive authentication is required; no other resources were touched.

The trusted host guardian or Docker daemon can still die or stall. A leaked controller pipe can delay detection until the fixture deadline; same-user access to Docker grants broad authority; persistent identity, independent authenticated braking, immutable launch policy, cross-identity authority, all-path migration denial, reliable host restart recovery, and filesystem/network isolation against hostile workloads remain unproved. A `populated 0` read proves only the observed subtree at that time and cannot rule out earlier escape. Production remains fail-closed.
