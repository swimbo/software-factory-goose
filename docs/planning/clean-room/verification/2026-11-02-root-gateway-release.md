# Root gateway release checkpoint

The private `_release_gateway` path consumes a prepared gate only after matching the saved grant, scope, attached-child receipt, gate inode and deadline. It checks the current Root scope, guard identity, child identity, exact cgroup leaf and unfrozen parent before persisting a one-use release intent, repeats authority and child checks, and sends one release byte. It consumes the gate on every path. An unknown write or receipt outcome requires fencing and reconciliation; it is not permission to retry. The caller must retain the direct child without concurrent reaping and own the gate's sole writer.

Component tests reject a substituted pipe, a pipe swapped immediately before release, duplicate release and guard loss after intent. Pipe inode checks accept the full unsigned 64-bit range. A network-disabled Linux fixture executed the real preparation and release methods and observed the synthetic target's UID via broker `SO_PEERCRED`; its grant, guard and attachment checks were mocked. A separate native PID1 fixture exercised the actual prepared-child/cgroup inspection and rejected changed UID and leaf inode before releasing its synthetic target. The two fixtures do not establish the joined production launch, real Bifrost bootstrap, handed-socket cleanup, route custody or provider bounds. The release method is private and is not exposed to production admission. No paid calls occurred.
