# NUC delegated cgroup fixture

On the authorized NUC, `sudo -n` was unavailable. A random transient user unit with `Delegate=yes` created only two child cgroups inside its own delegated subtree. `ssh -o BatchMode=yes hermes-control python3 - < clean-room/tests/fixtures/nuc_delegated_cgroup_spike.py` passed twice; after each run the test stopped and collected only its own named unit, and no fixture units remained. It used no new account, service installation, persistent data, container, or privileged operation.

The unit's guardian stayed outside its worker child cgroup. A directly owned worker leader forked a child that verified `setsid` and recorded its cgroup. In the positive control that child emitted a delayed marker. In the stop control the guardian killed and reaped its own direct leader, wrote `1` to the worker subtree's `cgroup.kill`, independently read stable `populated 0` from that still-existing child cgroup, and observed no delayed marker. The parent cgroup stayed alive for observation, avoiding the earlier ENODEV race. This proves the tested worker subtree was empty at that point while the guardian and systemd user manager were alive; it does not prove teardown after their failure.

In a negative control, a directly owned same-UID child wrote its own PID to the task-owned sibling's `cgroup.procs` and moved there. The observer saw `worker populated 0` while the child was still alive in sibling. The guardian retained the direct `Child` handle and killed/reaped it before cleanup; no saved or unowned PID was signalled. The NUC user-manager parent cgroup's `cgroup.procs` is owned and writable by bo, and the common-ancestor rule documented by the [Linux kernel](https://docs.kernel.org/admin-guide/cgroup-v2.html#delegation) makes escape from the intended tree a serious concern. The test did not move a process into an existing shared cgroup; external migration is an inference, not a demonstrated result. Same-UID delegation fails the hostile-worker boundary.

The result neither implements protected distinct identity nor proves outer guardian/manager death, external job creation, authenticated independent braking, migration denial, persistent recovery, or filesystem/network isolation. Production remains fail-closed.
