# Private runtime genesis and reservation evidence

On the NUC, a disposable fresh PostgreSQL 17.11 cluster with Unix-only access ran the exact `private_database_genesis::initialize_fresh` migration and privilege code. Repeating genesis was denied. The `sfactory` application role could insert and read the outbox and insert/update the claim projection; attempts to create a table, read audit events, delete the outbox, execute `COPY ... PROGRAM`, and assume the admin role were denied. The disposable cluster was stopped and removed. Log: `/tmp/sfactory-runtime-build.PjU7pCOX/genesis-fixture.log`. This tests SQL privileges, not systemd, network namespace, peer mapping or deployed PostgreSQL recovery.

The root-provisioned runtime now validates the root-pinned boot ID and refuses intake/worker handling until a root-owned bootstrap-complete marker with exact bytes, owner, mode, single link and no ACL is visible. Linux tests for the marker and named socket descriptor ordering passed in `/tmp/sfactory-runtime-build.PjU7pCOX/test-gated-runtime.log`. The fixed disposable bootstrap also records fresh PostgreSQL system ID and data directory identity, but the runtime does not yet revalidate PostgreSQL/Restate identity on every restart. This is a canary boundary, not production recovery acceptance.

A separate fresh Restate/PostgreSQL integration run exercised the same authoritative ClaimLeaseJournal's optional root-catalog launch reservation: wrong proof denied, response lost before identical retry, exact grant replayed, and subsequent claim/renew/complete refused. After lease expiry and Restate restart, mutation remained refused. `launch_reservation_replay.py` is the reproducible fixture; the reservation is disabled by default. It has no root-grant endpoint, root-side single-use consumption, deadline enforcement, closure receipt or clearing protocol. It does not authorize a worker launch or prove a complete production INT-LOOP.

A second disposable NUC test used an actual local peer mapping for the current OS user, a randomly allocated loopback port and the proposed HBA ordering. It verified Unix-mapped admin access, refusal of TCP admin, and permitted limited TCP application access. Log: `/tmp/sfactory-runtime-build.PjU7pCOX/genesis-auth-spike.log`; fixture: `clean-room/tests/fixtures/nuc_pg_genesis_auth_spike.py`. This does not establish the production journal UID's mapping or systemd namespace.

The reviewed private canary was recovered on the same PostgreSQL system ID and later passed a real `sfctl` UID1000 intake/inspect and UID2001 worker claim replay. A root-owned exact-runtime-only restart changed the runtime PID while keeping PostgreSQL, Restate, namespace-anchor and socket identities fixed; the exact worker claim replay passed afterward. Evidence: NUC `/tmp/sfactory-private-acceptance-before.log`, `/tmp/sfactory-private-acceptance-after.log`, and root restart receipt `/tmp/sfactory-private-restart-apply-envelope.json` on the local workspace. This is a scoped canary, not a Goose execution or promotion.

A candidate root grant endpoint was exercised against a disposable Restate/PostgreSQL journal with actual UID0 and UID2001 Unix peers, including a partial unauthorized body, wrong generation, no-reservation renewal control, lost acknowledgement, replay and journal restart. A separate two-catalog upgrade fixture registered a new SDK URI without force while retaining the old SDK, and confirmed old intake/queue replay and new qualified task/root grant across journal restart. Logs on NUC: `/tmp/sfactory-root-grant-journal-spike2.log` and `/tmp/sfactory-two-catalog-upgrade3.log`. The candidate binds intent, queue, task, generation, worker, repository/base and the entire qualified catalog fingerprint. It has not been installed in the live canary; root consumption, independent deadline and authenticated closure remain absent.

The broad Linux control-plane library run passed 216 tests and failed ten promotion execution tests because that module's non-macOS ACL implementation currently returns a fail-closed error; one test was ignored. The focused Linux sidecar checks and strict Clippy passed. Linux promotion remains a real unresolved implementation gate.
