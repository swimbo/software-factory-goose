# Bounded promotion eligibility and exact-ref binding

Date: 2026-10-27. Component work only; no endpoint, worker or standing repository was activated.

`control-plane::promotion_eligibility` derives a promotion action from a trusted current snapshot and evaluator/prefilter summaries. It requires awaiting-promotion state, no stop or active claim, a nonzero authoritative generation, distinct base/candidate revisions, passing deterministic checks for the exact candidate, and a passing prefilter bound to the current candidate and manifest. Revalidation reconstructs the action before consuming the stored approval; failure leaves the record untouched. Existing operator identity, expiry, audience, exact-presentation and single-use checks remain required.

The SHA-256 digest covers a versioned, deterministically serialized **summary**, including task, repository identity, target ref, base/candidate, manifest, generation and passing check fields. It is not a signature or raw-transcript hash. Trusted integrations must increment the generation whenever state/evidence changes, read authenticated sources and persist decisions under exclusive access. No request deserializer exists for the snapshot or revalidated result. Public Rust constructors remain an internal trust boundary, not proof of execution or provenance.

Inspection found that the legacy evaluator helper selected the repository's HEAD branch although an approval binds an explicit target ref. New `promote_verified_commit_to_ref` advances only the specified `refs/heads/...` target using `update-ref --no-deref` and expected-old CAS. It refuses symbolic targets. The compatibility wrapper remains, but action-bound integrations must use the explicit API. A disposable bare-Git fixture switches HEAD to another branch and proves only the approved branch advances; malformed targets, symbolic aliases and stale bases fail.

Test-first evidence: the new imports initially failed compilation because the APIs did not exist. Seven eligibility fixtures then passed, covering malformed/ineligible state, failed/stale evidence, changed authoritative bindings, forged presentation, wrong identity/audience, expiry and replay. Three promotion fixtures passed, including the explicit-ref regression.

Remaining gates: trusted/durable snapshot and evidence loading; real holdout runner/store isolation; exact repository-identity-to-protected-path resolution; per-request Unix peer authentication; private Restate ingress; atomic journaled decision/external mutation reconciliation; and supervisor/budget gates. Git CAS prevents stale target-base updates; it does not close races in task eligibility or make a consumed approval proof that mutation completed. The pure adapter does not call Git or authorize deployment.
