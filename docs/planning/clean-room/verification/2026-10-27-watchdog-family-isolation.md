# Watchdog family stop isolation

The previous registry held a global mutex for the full two-second stop wait. A test with an intentionally unresolved, already-reaped family and a separately owned live sleep process failed before the change: stopping the unrelated family waited 2.014 seconds. No nonzero signal was sent to the reaped PID. The same test passed after moving family ownership and cleanup under individual locks, with the registry index held only for lookup. Admission and stop for the same family still serialize, and spawned children retain sole-reaper ownership.

The brake fixture limits in-flight stop tasks to 16; an exhausted semaphore returns 429 and accepts a subsequent request after a permit is released. Family and index locks use nonblocking acquisition in the HTTP path, so repeated requests for a busy family return conflict instead of occupying every stop permit waiting on its lock. A test made 32 requests against a deliberately locked family and then successfully stopped another family. Capacity exhaustion remains a temporary denial of service, not a termination claim.

The real blocked-pre-exec canary also stopped a separately owned family while the first family had an unresolved launch, rejected another launch to the closed first family, and stopped the late returned child after releasing setup. The final watchdog run passed 24 tests, strict all-target/all-feature Clippy, and the canary using locked offline dependencies. Both family-lock and index-poison paths retain and attempt owned cleanup for a child returning from spawn.

These are same-UID tests of the fixture, not a production brake or containment boundary. The pending child is not stopped before `spawn` returns and may briefly execute afterward. A hung or poisoned index makes lookups fail, all 16 active operations can saturate the bounded endpoint, and a poisoned family requires recovery. Process exit or SIGKILL bypasses Rust `Drop`; the registry cannot reconstruct safe ownership from stored numeric PIDs, and no independent owner-loss cleanup has been demonstrated. Escaped descendants, cross-UID authority, blocked kernel calls, and complete containment remain open.
