# Unix-admin synthetic SDK fixture evidence

The pinned Restate Unix-admin fixture is separate from the existing factory journal. Its phase-one permission check reported a UID2004-owned mode0700 admin socket, denial to UID2000 and no TCP admin listener. The synthetic SDK package was installed but not registered or used for journal mutations.

The first SDK startup preflight failed before listening; its root-only log classified an unexpected descriptor. Both preflight and connector units were observed failed with PID0 and no job; the extra-descriptor negative control did not run. The original preflight intent remains retained. Read-only receipt: `/tmp/sfactory-unix-admin-sdk-preflight-inventory-envelope.json`.

A distinct UID2000 capability-free/NNP diagnostic using the same Tokio runtime reported three Unix sockets, two eventpoll descriptors and one eventfd before async main. Receipt: `/tmp/sfactory-unix-admin-sdk-fd-diagnostic-apply2-envelope.json`; this diagnostic started no listener and sent no registration. This supports moving the inherited-descriptor check before Tokio construction; it does not identify the contents of the original rejected descriptor.

The versioned v4 candidate now scans before creating Tokio and refuses every inherited descriptor above stdio, including sockets. Its Linux locked/offline build passed and the stripped candidate is `/tmp/sfactory-ingress-sdk-20261030/ingress-fence-sdk-v4.stripped` SHA-256 `3756d5cbe5f4bb3dfc4a735cc45b30cdff076f2d812ef3f57ea7bea2952dc611`; source SHA-256 `417680f4a740f74962b28c77da08a4d499aea4c55aa6446ca405b4742cc2f42b`. It has not yet passed its own UID2000 native startup or extra-FD negative control. The prior installed SDK remains unchanged.

The subsequent v4 native preflight passed normal startup/listening and rejected an inherited extra descriptor before binding. The epoch2 combined orchestration then installed its fixed helpers, started its owned network/Restate and old SDK, proved the old URI absent, and registered the old SDK. It failed at the positive probe. The retained outer receipt is `/tmp/sfactory-identity-admin-1c4f6x34`; no retirement, new registration, or restart stage ran, and the attempt must not be replayed.

Read-only failure inventory and snapshot showed the probe terminal, zero invocations, zero queue entries, and no counter rows. A sanitized trace located the reset at the first direct HTTP/1.1 discovery request, before any invocation POST. The locked Rust SDK 0.12.1 server uses Hyper's HTTP/2-only connection builder. An independent native HTTP/2 prior-knowledge discovery check succeeded against the same old SDK (`/tmp/sfactory-identity-admin-tfjz3tmu`), confirming the protocol mismatch without invoking a service. This establishes the failure cause, not retirement acceptance.

The exact reviewed failure-quiesce APPLY succeeded at `/tmp/sfactory-identity-admin-p1fvxoer`: owned units terminal, SDK listeners closed, admin socket absent, and fixture data retained. Registration was not retried and the original result remains unknown. A fresh isolated namespace and toy SDK are being prepared for the corrected HTTP/2 keeper; they do not reuse or clear the failed attempt's intent or retirement fence. Existing production services and data were not changed by these fixture operations.
