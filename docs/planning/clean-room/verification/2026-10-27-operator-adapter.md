# G05 bounded operator approval adapter

Date: 2026-10-27. Feature-gated, unregistered approval-only library adapter. No Git action, worker launch, credential issuance, budget change, account provisioning or runtime registration is enabled.

`operator_adapter::operator_router` accepts an `OperatorPolicy` obtained from the existing protected socket binder, a trusted configuration, a `PromotionAuthority` and an `ApprovalBackend`. Construction verifies the actual service UID, requires distinct nonroot service/operator/generator/evaluator identities, and bounds the audience, approval TTL and request deadline. Serving must use `OperatorPeer` connection metadata. The existing transport middleware derives the peer UID from the actual accepted Unix connection; each handler then checks that authenticated UID against adapter configuration. Missing/mismatched kernel identity denies before approval/evidence access. No request header or body can establish authority.

There are exactly three routes, with a16KiB input cap and configured10ms–30s total request deadline:

- `POST /prepare` accepts only task ID and presentation reason. The authority resolves and holds the task/evidence guard. `prepare_promotion` derives the repository, branch, exact candidate/base revisions and evidence digest from that server-held state. The adapter generates a fresh nonce and asks the journal to issue the fixed configured lifetime. It validates returned identity, audience, action, nonce, lifetime and unconsumed state before returning an action presentation with a versioned SHA-256 presentation digest.
- `POST /consume` accepts only nonce and that presentation digest. It reads the stored journal record, checks its binding to the actual operator and audience, acquires fresh authoritative state/evidence, and calls the existing pure eligibility/consumption checks before calling the durable journal. Changed generation, action, presentation, state, expiry or prior consumption refuses. Success reports a consumed approval and `execution: not_executed`; no executable promotion token or Git method is exposed.
- `POST /status` is authenticated inspection of the selected journal record. It returns the stored consumption state after identity/audience validation. A consumed record is never a fresh execution permission.

`UnixApprovalBackend` supplies narrow fixed calls to existing `ApprovalJournal.issue`, `.status` and `.consume` through the protected, bounded Unix Restate transport. The underlying generic call method is crate-private; no generic forwarding route is exposed. No-argument status omits the body. The existing transport checks socket ownership/modes/ACLs and inode identity and performs a kernel peer preflight. As documented in that transport, reqwest does not expose the credentials of its subsequent HTTP connection; its protection depends on trusted non-writable ancestors and the service principal. This is not proof that a loopback Restate/admin upstream is inaccessible to workers.

Ambiguous outcomes: the journal may have persisted issuance or consumption even when its acknowledgement is lost. The adapter returns503 with `approval_outcome_unknown`, the nonce and no approval presentation/execution result. An operator can inspect `/status`; retries cannot clear a consumed record. If the outer HTTP issuance response itself is entirely lost, the client may not know the server-generated nonce; no durable client-request-to-nonce recovery index is supplied. Preparing again can create another short-lived record, but cannot execute a mutation through this adapter.

Test-first evidence: initial tests failed because the adapter did not exist. Ten focused tests now pass using actual local Unix listeners/kernel credentials and an in-memory journal/authority fixture: authenticated server-derived presentation and one consumption; missing context; actual peer mismatch despite a forged header; forbidden UID/revision/evidence fields; changed generation/stopped state; altered presentation; oversized requests/expiry; mismatched journal identity/audience without disclosing a record; persisted issuance with lost acknowledgement and nonce recovery; persisted consumption with lost acknowledgement, inspection and replay refusal; local guard retention during the call and release after timeout. `cargo test -p control-plane --features restate --lib operator_adapter` passed10 tests. `cargo clippy -p control-plane --features restate --lib -- -D warnings` passed.

The successful route fixture uses a private test-only policy factory and deliberately synthetic runtime UID configuration so the actual current UID can act as the operator in one process. The public constructor has no same-UID bypass. These tests establish protocol behavior, not separately provisioned accounts, group access, production ingress, human presence or MFA. Journal failure injection is a stub, not another Restate crash test.

Regression result: `cargo test -p control-plane --features restate --lib` passed117 tests with none ignored, including existing approval, transport, worker, claim and journal logic. `git diff --check` passed. No broader activation claim follows from this library suite.

Remaining boundary: no production `PromotionAuthority` implementation is supplied. Its guard must exclude all eligibility/evidence writers and advance generation for every change. A local mutex test does not establish durable cross-service locking. On timeout/cancellation, a remote journal invocation can continue after the local guard drops; therefore this adapter does not establish atomic revalidation plus durable consume plus Git execution. It deliberately performs no external action. A durable decision/reconciliation protocol, authoritative source integration, protected private ingress, full separate-account canaries and exact-SHA execution/recovery remain required before a promotion runtime can be enabled. Budget and credential approvals are outside this narrow adapter.
