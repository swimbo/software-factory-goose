# NUC protected containment prerequisites — proposal, not installed

The review target is a task-owned delegated cgroup tree whose live-process observation survives a worker owner's death. The untrusted worker must run under a distinct, non-root, non-shared UID and have no write permission to the protected subtree's parent or any ancestor `cgroup.procs`, no capability to move tasks or create work outside the subtree, and no access to the lifecycle authority's socket or credentials. A privileged lifecycle authority must create a fresh uniquely identified parent and worker subgroup, place the worker in the worker cgroup **before any untrusted instruction**, drop supplementary groups/GID/UID and capabilities before exec, close inherited authority descriptors, and refuse launch on any failure. The [unit sketch](sfactory-containment.service.example) is deliberately inert and references software that does not yet exist.

The lifecycle authority must remain outside the worker subtree, close admission before stop, write `cgroup.kill`, and independently observe `cgroup.events populated 0` on the same protected, persistent subtree. A separate authenticated stop/recovery authority must retain or recover that subtree identity if the worker owner fails; neither a stale PID nor a container exit status is sufficient. The design must explicitly handle death or suspension of the outer authority itself: do not mark cleanup successful merely because systemd removed its cgroup. Preserve quarantine until a surviving authority has an accepted teardown proof. This recovery authority, authority separation, atomic placement and trusted executable are unimplemented.

## Root-reviewed provisioning sequence

1. Review a fixed service/worker account name and UID/GID allocation against existing NSS, groups and resources; abort on any collision. Create a dedicated locked, non-login system account and group only after review; record returned IDs and exact created resources in a protected task-owned manifest. Do not modify existing accounts or reuse an interactive UID. Ensure the worker has no supplementary groups or Docker/systemd-management privileges.
2. Review and install the real supervisor binary, configuration, unit and a separately authenticated stop/recovery channel using root-owned, non-writable paths and protected ancestors. The example unit is not deployment-ready; its `Type=notify` and enable condition require an implementation and review. `Delegate=yes` alone neither enforces a UID boundary nor provides a stop authority. Do not enable the worker on install.
3. As root, create and protect each task-owned cgroup tree and its membership/migration interfaces; ensure the worker UID cannot write the delegated root or common ancestor cgroup.procs, mount or access a broader hierarchy, or submit external jobs. Keep the controller outside the worker subgroup and the observation path alive through stop. A safe atomic launch implementation and fd/path identity checks must precede any hostile input.
4. Establish bounded fail-closed lifecycle and recovery with a separate principal/authority. Crash, timeout, unavailable permissions, changed paths, reused IDs and ambiguous acknowledgements must retain quarantine; no numeric PID replay after restart. Preserve journal evidence and expose no secrets in argv or logs.

## Required disposable validation

Prove a benign no-kill marker, then repeated owner SIGKILL and worker `setsid`/nested-fork tests with `populated 0` on the same persistent child cgroup and no marker. As the actual worker UID, attempt movement to a task-owned sibling and outside the protected root; attempts must fail while positive authorized-management controls succeed. Test launch/stop/fork races, workers spawned before containment, controller/guardian/observer death and suspension, `cgroup.kill` errors, tampering, manager or host restart, no readmission before observed empty, and a separately authenticated brake while ordinary services are down. Verify network and filesystem negative controls independently. Any unknown or failure keeps the gate closed.

## Scoped rollback

Stop and remove only units whose names, binary/config paths and random task identity match the recorded provisioning manifest; first confirm worker subtree is empty using the accepted independent authority. Remove only the created empty cgroup directories, socket/runtime directory and installed files matching recorded identity/digests. Remove the dedicated account/group only after checking its exact recorded numeric IDs and confirming no owned processes or remaining dependencies. If any identity, live process, teardown, or dependency is ambiguous, stop rollback and retain the resource for explicit recovery. Never reset all failed units, prune Docker, alter existing services/accounts, or remove shared cgroups. No provisioning or rollback has been executed.
