# Application security research: Goose tool boundary

Research date: 2026-10-27. Reviewed the decision brief, locked R13/R14, local execution policy/mask modules, and Goose source pinned to `71fc4be1ed729e26b1dc0a4466abdd03be548a53` (v1.49.0). No Goose task, external model, privileged operation or canary was executed. Evidence is **STRONG for rejecting hooks-only enforcement; ADEQUATE for choosing a bounded comparative spike; INSUFFICIENT for activation**. Position awaits the shared ledger.

## Evidence summary

1. **Policy and masking are mandatory contracts.** R13 requires pre-execution gating of every shell command and an OS backstop; R14 requires scrubbing tool outputs before model context. Current policy explicitly admits it is a partial filter, not an AST parser or sandbox; current masker is finite regex matching, not general DLP. Sources: `../../consensus-plan.md` R13/R14; `clean-room/crates/execution/src/{policy,mask}.rs`, read today. Inference: adding a transport does not make this parser complete or prevent code invoked by an allowed build tool from spawning children.
2. **No hook means allow; subagents intentionally have no hooks.** Pinned pre-tool code returns `HookChainOutcome::allow(false)` when no matching hook is loaded. The subagent constructor selects the default empty manager. Sources: [tool operations](https://github.com/aaif-goose/goose/blob/71fc4be1ed729e26b1dc0a4466abdd03be548a53/crates/goose/src/agents/state_machine/ops_toolcalling.rs), [agent constructor](https://github.com/aaif-goose/goose/blob/71fc4be1ed729e26b1dc0a4466abdd03be548a53/crates/goose/src/agents/agent.rs), pinned release published 2026-09-03 per the provenance report.
3. **Post-tool hooks cannot substitute sanitized content.** `with_post_tool_hooks` processes a result, records telemetry, emits hooks, then returns that result. Notification and action-required streams pass through separately. This establishes a mandatory-enforcement gap; it does not prove every notification is sent to a model. Source: tool operations above, local lines 235–310. A patch placed after telemetry/large-response processing may still leak into earlier sinks.
4. **Restricted tool availability has an actual dispatch check.** `dispatch_tool_call` resolves the tool, then checks extension `is_tool_available` before `client.call_tool`. Resolution includes recovery of mangled names. It subscribes to client notifications and combines request notifications; result errors include underlying error text/data. Source: [extension manager](https://github.com/aaif-goose/goose/blob/71fc4be1ed729e26b1dc0a4466abdd03be548a53/crates/goose/src/agents/extension_manager.rs), local lines 2210–2420. This supports testing an allowlisted surface; it does not establish immutable extension configuration or comprehensive coverage of other operations.
5. **PATH interception is incomplete.** The developer shell selects `GOOSE_SHELL`, otherwise bash/sh, and can emit live output. `--no-profile` promises exclusion of default extensions, not all execution paths. Sources: [shell](https://github.com/aaif-goose/goose/blob/71fc4be1ed729e26b1dc0a4466abdd03be548a53/crates/goose/src/agents/platform_extensions/developer/shell.rs), [CLI](https://github.com/aaif-goose/goose/blob/71fc4be1ed729e26b1dc0a4466abdd03be548a53/crates/goose-cli/src/cli.rs), and `../../verification/2026-10-26-goose-protocol.md`.
6. **Tool results are not necessarily strings.** MCP defines text, image, audio, resource links, embedded resources and structured JSON; protocol errors and tool execution errors are distinct. It requires server access checks/output sanitization and recommends client validation before LLM use. Source: [MCP tools specification, 2025-06-18](https://modelcontextprotocol.io/specification/2025-06-18/server/tools), accessed today. This is a content-channel checklist, not a claim Goose implements every revision feature identically.
7. **Resources form another content path.** Extension manager exposes resource reads and MCP-app resource hydration in addition to ordinary tool calls; a final text-only mask cannot be assumed to cover them. Source: extension manager above, local lines 1879, 2002–2051, 2398–2414. Unknown types must be refused or specifically sanitized, not coerced to unexamined blobs.
8. **A success label is not success evidence.** The pinned CLI breaks its response loop after cancellation/stream error and subsequently emits `completed`; cost may be unavailable. Source: [session loop](https://github.com/aaif-goose/goose/blob/71fc4be1ed729e26b1dc0a4466abdd03be548a53/crates/goose-cli/src/session/mod.rs), plus protocol report. Reject absent cost, incomplete tool pairs and unobserved termination; retain independent exact-SHA verification. Source inspection is not a source-to-release-binary attestation.

## Option matrix

| Option | Evidence and fit | Main risk / required proof |
|---|---|---|
| Hooks/PATH only | Proven insufficient for locked requirements | Empty/subagent hook path; no replacement output API; other shells/tools |
| Protected factory MCP tools only, OS backstop | Dispatch availability check supports a narrow spike; preserves Goose | Prove full reachable surface, no re-enablement/nested bypass, exclusive provider route, immutable broker/config and every output channel |
| Pinned minimal patch/library integration | Can place mandatory checks and normalization in code by construction; no implementation reviewed | Multiple paths and earlier telemetry/resource sinks; dependency maintenance and source/binary provenance; same OS backstop still required |
| Version change only | No release evidence establishes repaired contracts | Repeats assumptions without proving behavior; reject as a solution alone |

## Proof gaps and smallest spike

Use a disposable workspace, synthetic sentinels, a factory MCP fixture and a deterministic recording provider endpoint. Keep real credentials, Bifrost and standing services out of the experiment. Require an allowed operation to produce an independently observed marker and provider request before interpreting any negative check.

Test (a) forbidden commands, absolute paths, alternate shells/interpreters, nested tools, subagents, recipes and attempted extension enablement; (b) synthetic secrets in stdout/stderr, successful/error content, JSON fields, resource reads, unsupported media and notifications; (c) secrets split across chunks and truncation boundaries; (d) missing/malformed policy, unavailable mask/broker and cancellation during output; (e) provider disconnect, error, timeout and missing usage. Observe filesystem/process/network side effects independently of Goose text. Inspect every recording-provider request, not just the final response. If a channel is deliberately disabled, prove refusal of a direct call, including recovered tool names.

The regex masker cannot guarantee protection against arbitrary encoding or malicious transformation of readable data. Preserve prevention of real secret access as a separate requirement. A canary passing known formats establishes that finite contract only. Clarify whether R13 means every model-requested shell operation or every descendant process execution: neither an AST wrapper nor a normal tool-dispatch patch automatically mediates the latter. Do not silently weaken the accepted wording.

Preliminary recommendation: compare the restricted-tool spike against a narrowly scoped patch only after full surface enumeration. Prefer the restricted option if its negative paths pass; otherwise retain blocked execution and specify the minimum patch. Neither recommendation authorizes workers.
