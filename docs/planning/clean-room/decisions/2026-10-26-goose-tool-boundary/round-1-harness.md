# Round 1 — harness response

Date: 2026-10-27. Responding to [security](position-security.md), [operations](position-operations.md), and the [shared ledger](evidence-ledger.md). We agree on the experiment-first decision. The remaining disagreement is how precisely to delimit success and stop conditions, not whether flags prove safety.

**I maintain my position that restricted stock Goose deserves the first bounded test.** Security correctly warns against declaring a patch necessary before testing the launch arrangement. The [fresh-session extension branch](https://github.com/aaif-goose/goose/blob/71fc4be1ed729e26b1dc0a4466abdd03be548a53/crates/goose-cli/src/session/builder.rs#L568-L625) gives this experiment a concrete basis. But a protected launch directory is a hypothesis, not an exemption from the project-plugin canary. Acceptance requires the recorded inventory to contain only approved factory tools and independently observed absence of forbidden effects after direct calls, recovered names, attempted reconfiguration, resume, and project-plugin insertion. A missing provider request or failed positive-control tool invalidates the experiment rather than passing it.

**I concede that my earlier emphasis on a terminal-error backport could suggest premature patch selection.** The newer [terminal-error implementation](https://github.com/aaif-goose/goose/blob/9949cf926cd42f1d128b9991ed23a496ecace896/crates/goose-cli/src/session/mod.rs#L1558-L1679) is a comparison target only. First demonstrate the pinned binary's behavior with scripted provider failure and cancellation. If the approved launcher can independently distinguish those failures without relying on ambiguous stdout, assess that narrower arrangement. If it cannot, stop the receipt candidate and specify the minimum patch. A newer release is not selected automatically.

**I maintain that output ownership must precede Goose processing.** Security's concern about earlier telemetry and resource sinks rules out a post-hook mask. The [wrapper retains result and notification paths](https://github.com/aaif-goose/goose/blob/71fc4be1ed729e26b1dc0a4466abdd03be548a53/crates/goose/src/agents/state_machine/ops_toolcalling.rs#L237-L310). Acceptance therefore requires synthetic secrets to be absent from every recorded provider request and every designated evidence sink after successful, error, structured, notification, split-chunk, and truncation inputs. Unsupported content must be explicitly refused. One leaked sentinel falsifies that content path; a finite passing matrix establishes only its documented formats, not universal DLP.

**I concede operations' stronger recovery requirement: observed parent exit alone is insufficient.** The experiment must observe tool processes and retained pipes, inject failure after side effect but before response, and prevent a late response from attaching to another attempt. Cancellation without confirmed cleanup preserves an unknown/quarantined outcome and budget reservation; it cannot justify reassignment. These are acceptance requirements, not assertions that the existing supervisor already implements them.

One distinction needs preservation: a deliberately denied tool request or an ordinary test-command failure is not necessarily a broken harness. The proposed contract should separate bounded, correlated tool outcomes that the agent may handle from infrastructure failures that leave execution or accounting unknown. A later assistant message must never clear an unresolved infrastructure fault. Successful generation requires explicit terminal evidence, complete accounting, no unresolved operations, confirmed cleanup, and independently obtained candidate identity; artifact correctness still belongs to wall verification.

**I maintain the R13 blocker unless its literal coverage is demonstrated.** Both reviewers correctly distinguish top-level policy decisions from repository-controlled descendant execution. A stock-tool or patched-dispatch pass cannot silently close the latter. Record mediation coverage and OS effect constraints separately and retain the unresolved requirement.

Final decision rule: permit the offline experiment; accept only its enumerated boundary evidence; stop a candidate on any bypass, leak, false receipt, or unreconciled lifetime/accounting result. Select a patch only against a named reproduced failure. Live execution remains disabled regardless of this round's consensus.
