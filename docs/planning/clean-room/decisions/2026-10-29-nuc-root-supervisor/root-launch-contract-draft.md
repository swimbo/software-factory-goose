# Root launch authority: review draft

Status: **not an admission mechanism**. The private runtime has no root-verifiable claim-to-generation grant, consumed receipt, expiry or revocation contract. Until that exists, no UID 2000 launch socket or root launch service may be exposed. This draft defines a small implementation seam and the tests required before wiring it to effects.

The public request should contain only a canonical opaque generation ULID. Kernel peer UID identifies the control caller but cannot by itself authorize execution. The backend must retrieve a root-owned immutable record for that generation: task and claim/lease identity, current boot, cgroup device/inode, exact root-approved recipe digest, issuer evidence and a unique grant ID. It must verify the record and **a fresh authoritative claim** through a separately reviewed issuer or verifier unavailable to workers. It must reject unavailable, expired, revoked, consumed, conflicting, ambiguous and unverifiable claims. A caller-supplied string or root-owned snapshot of an obsolete claim is not freshness proof. No API accepts commands, paths, images, mounts, PIDs, environment, Docker options or unit names.

A minimal internal interface should express `authorize(target) -> BoundGrant`, `create_intent(BoundGrant) -> ReservedGeneration`, `create_stopped(ReservedGeneration) -> ExactOwnedId`, `seal(ExactOwnedId) -> SealedGeneration`, and `start(SealedGeneration) -> StartedOrUnknown`. These are internal authority-owned types, never serialized as caller-selected capability objects. Each method must reload or pin the protected identity and check the permanent stop closure before and after external effects. Record and fsync the unique, single-use intent before create; a create timeout or lost reply is **unknown**, never a reason to retry or start. Verify returned full container ID, immutable recipe, name, ownership label, image, cgroup target and daemon identity, and durably fsync the seal before start. A failed or lost start acknowledgement remains unknown; closure is checked after the return and before any success response.

Serialize launch for a generation with `<target>.lock` across creation/start. Root stop uses the separate `<target>.stop.lock` and establishes `<target>.closed` before freeze, so a blocked daemon request cannot block the brake. The cgroup is created and inode-bound before the grant can authorize effects, is never recreated for that generation, and remains frozen on a stop or uncertain operation. A closure check by itself cannot cancel an in-flight daemon request; late start is confined by the protected frozen cgroup until the exact engine object is authoritatively reconciled. Do not thaw, remove the cgroup, report terminal engine cleanup or readmit the generation merely because the client timed out or observed empty once.

Durable recovery starts closed: scan root-owned intent/seal/closure records, validate boot and immutable identities, and quarantine every unresolved create/start or incomplete grant consumption. Recovery may only inspect or remove an exact known owned ID after matching immutable name, label, recipe and daemon; unknown create requires its own reviewed name-reservation/reconciliation proof. A new process, helper restart, stale lease or crash must not mint a second launch or silently clear a closure. A reboot changes boot identity and invalidates previous inode assertions; boot recovery requires a separate reconciliation protocol. No power-loss guarantee follows from process-crash tests or fsync calls alone.

Required falsifiable controls before production exposure:

- Wrong UID, unknown/noncanonical target, caller-chosen command/path, catalogue substitution, changed recipe, mismatched boot/cgroup inode, wrong task/claim/generation, expired/revoked grant and replay must deny **before** any engine effect. Stop closures permanently deny all subsequent launch attempts, including concurrent waiters.
- A real blocked create/start while holding the launch lock must not block root stop; its late completion must not produce success or execute an instruction outside the already frozen bound subtree. Independently observe actual child scope, first-instruction marker and same-inode cgroup state. A successful no-stop positive control must execute the marker.
- Kill the launcher after intent, during create, after create before seal, after seal, during start, and after dispatch before reply. Restart the actual service and prove no second dispatch, no release of unknown effects, and exact-owned recovery only. Inject daemon unavailability and lost acknowledgements; distinguish simulated endpoint outages from host/daemon failure.
- Test durable claim revocation and consumption races against start, including verifier loss and clock uncertainty, once their authoritative semantics exist. Verify isolated service UIDs cannot forge a grant or write the root catalogue, closure or recipe; check no credential or authority socket reaches the worker.

The root stop V2 native held-lock test demonstrates independent kernel stop with a native setsid descendant and a deliberately unavailable Docker socket in that service's mount namespace. It does not prove the launcher, claim freshness, Docker late starts, daemon or host recovery.
