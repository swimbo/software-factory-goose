# Security research: independent brake caller amendment

**Preliminary position:** B is the least additional privileged machinery if, and only if, a separately named production policy explicitly admits the existing operator UID for the stop channel and the independently held stop bearer remains unavailable to the worker and control identities. The existing `BrakePolicy` must stay unchanged and its distinct-ordinary-operator contract must not be presented as satisfied by B. This is a policy distinction requiring the debate and tests; it is not an adopted decision or production approval.

## Controlling evidence

1. R9 requires an independent brake credential and separate watchdog, not dependent on the operator token; it specifically says an agent with an exfiltrated operator token cannot reach the brake key. [R9](../../consensus-plan.md#r9--kill-switch--kill--pgid--an-out-of-band-brake-key). The user's later O4 selection specifies a separate local operator and action-bound approval channel, explicitly excludes MFA and same-UID-compromise claims. [O4 decision](../2026-10-26-operator-auth/consensus-plan.md#post-debate-user-decision-supersedes-unresolved-mechanism-selection-only). These are separate constraints: token theft is within R9's scenario; full bo-account/Docker-root compromise is outside the chosen O4 assurance.
2. The current [BrakePolicy constructor](../../../../../clean-room/crates/watchdog/src/lib.rs) demands distinct nonroot service, brake and explicitly listed ordinary UIDs. Its documentation includes the ordinary operator among exclusions. The drafted frontend passes bo as the brake peer while omitting bo from that list: it compiles but does not preserve that documented contract. It is blocked and uninstalled.
3. Local Unix [`SO_PEERCRED`](https://man7.org/linux/man-pages/man7/unix.7.html) returns kernel peer credentials, a process identity rather than human presence or proof of what a bearer authorizes. A valid approval bearer without the stop bearer must fail; a valid stop bearer without the admitted local peer must also fail. The stop endpoint and root backend must remain independent of the control, database, gateway and Docker services.
4. Linux [`execve`](https://man7.org/linux/man-pages/man2/execve.2.html) preserves file descriptors by default, and ignores set-ID transitions under conditions including `no_new_privs`, `nosuid`, or tracing. [`setresuid/setresgid`](https://man7.org/linux/man-pages/man2/setresgid.2.html) must be checked for failure; supplementary groups must be dropped while privileged. A privileged client therefore introduces a real executable, loader, environment, inherited-FD and permanent-drop verification surface, even if its eventual request is fixed. A setuid canary must prove the effective peer after drop and failure when transition is suppressed, not infer it from mode bits.
5. [systemd's D-Bus API](https://www.freedesktop.org/software/systemd/man/257/org.freedesktop.systemd1.html) describes `StartTransientUnit` with unit properties and `SetUnitProperties`; these are broad capabilities unless a separately reviewed policy proves exact confinement. A polkit rule granting generic unit management is not automatically a fixed stop-only broker. The [systemd socket documentation](https://www.freedesktop.org/software/systemd/man/257/systemd.socket.html) also makes socket directory/owner/mode explicit configuration, separate from peer and bearer authentication.
6. NUC role identities 2000–2004 are reported provisioned and bo remains UID 1000 with existing Docker-group authority; exact host installation evidence is tracked in the identity verification artifact. The independent brake has prior cross-UID and synthetic relay-outage fixture results, not a provisioned human client or Docker/host failure proof. [Batch brake evidence](../../verification/2026-10-28-nuc-authenticated-batch-brake.md)

## Options and tradeoffs

| Option | Security case | Essential qualification |
| --- | --- | --- |
| A: setuid fixed client to distinct UID | Preserves the existing constructor's peer distinction and does not give the worker the bearer | Adds root-executed program and UID/GID 2005; must prove real UID checks, all groups/UID/GID and capabilities permanently dropped, no inherited descriptors or untrusted interpreter/command, fixed socket/target and correct behavior under nosuid, tracing and `no_new_privs` |
| B: explicit new bo-peer policy plus separate stop bearer | No new privileged client or identity; same real human login and independent stop-only server, with no claims of same-UID protection | It is a **different** policy from `BrakePolicy`, not an implementation of its stronger caller-exclusion contract. Need recorded applicability decision, private root-provisioned bo stop credential, strict proof no worker/control access, and stolen approval-only token plus wrong-peer/key denials |
| C: polkit/systemd or root broker | Potential distinct caller and fixed client without setuid bit | Need exact action/property confinement and noninteractive usability. Generic transient-unit or property rights would expand authority; an extra daemon also needs availability, authentication and recovery proof |

B fits R9/O4 **conditionally** because the controlling text demands a second credential independent of the operator token, not resistance to compromise of the entire bo UID. A separately named policy can make that interpretation explicit without weakening existing consumers. If the project separately requires the original constructor's *caller UID* distinction as an invariant for this deployment, B does not satisfy it; the team must select A or an equivalently narrow distinct-identity broker. Do not resolve that interpretation by quietly changing the existing type or its docs.

## Mandatory discriminators

- Provision the stop bearer independently of the action-approval bearer; root-owned secret distribution and a bo-only mode-0600 copy must not use argv, environment, logs, model prompts or repository. Check parent directories, no-follow inode/ownership and absence from worker, control, evaluator, journal and Docker mounts. A bo compromise can use bo-readable material and Docker-root privileges; do not claim otherwise.
- Exercise actual host UIDs and both endpoints: correct local caller plus correct stop key can stop an exact registered task; ordinary approval bearer alone, forged peer, wrong key, wrong role, unknown ID, arbitrary target/path and replay cannot trigger root mutation. Prove stop remains callable with a deliberately unavailable disposable Docker/control/database/gateway path; a prestarted synthetic client or mock is not human-operability proof.
- For A, include setuid program file ownership/mode/inode and no-writable-parent controls; root/bo real UID negative cases; post-drop real/effective/saved UID/GID, empty supplementary groups/capabilities, inaccessible key after drop except as designed, no arbitrary FDs or inherited environment, and no privilege regain. Test noninteractive host invocation and clean refusal under disabled setuid conditions. The first code executed by a setuid binary is privileged: do not place attacker-controlled dynamic library loading, scripts or parsing before the privilege boundary.
- For C, verify actual polkit action and method-level restrictions, unit template spec/identity, environmental/path substitutions, ability to call other units and set properties, denied wrong peer and replay. Do not grant `StartTransientUnit` or equivalent generic manager authority merely to gain usability.
- In every option root accepts only the authenticated frontend's dedicated UID and opaque canonical generation ID; kernel freeze/kill and `engine_reconciled=false` remain distinct. Test owner loss, socket activation and root backend restart separately. No user SSH key, shared Docker restart, gateway setting or production budget default is changed by the comparison.

Research only: no host mutations, service activation, secret provisioning, provider calls or acceptance claim occurred in this review.
