# Operations research: NUC root-owned supervisor

Research date: 2026-10-29. Read-only host check: Linux `6.12.107+deb13-amd64`, systemd `257.13-1~deb13u1`, Docker `29.8.0` server commit `3ce5872`, unified `cgroup2fs`; Docker, Hermes gateway and dashboard were active. This inventory does not prove installation authority, persistence after restart, or the security of shared Docker. No service or host configuration was changed.

## Material facts

1. In cgroup v2, writing `1` to `cgroup.freeze` freezes the group and descendants asynchronously; completion is reported by `cgroup.events` `frozen 1`. A process moved into a frozen group stops, but an authorized mover can move it out; a frozen empty cgroup can be deleted and children created. `cgroup.kill` kills the subtree and handles concurrent fork/migration, but a kill at one instant does not prevent a later accepted start. Keep the ancestor identity and freeze in place, prohibit untrusted migration, and prove the specific Docker/systemd late-start path. [Linux cgroup v2 documentation](https://docs.kernel.org/admin-guide/cgroup-v2.html).
2. systemd 257 documents `Slice=` hierarchy, `Delegate=` and unit resource limits; delegation changes who can manage a subtree and is not automatically safe for an adversarial worker. A unit stop with `KillMode=control-group` acts on its own cgroup; a separately managed Docker child under another slice cannot be assumed to be covered by the supervisor service's stop. [systemd.resource-control 257](https://www.freedesktop.org/software/systemd/man/257/systemd.resource-control.html), [systemd.kill 257](https://www.freedesktop.org/software/systemd/man/257/systemd.kill.html).
3. Docker `create` creates a stopped container and supports `--cgroup-parent`; `start` is a separate operation. A client timeout is not a daemon cancellation receipt. The project has already observed a timed-out create appear later, so preserve its intent and treat unresolved daemon work as unknown. [Docker create](https://docs.docker.com/reference/cli/docker/container/create/), [observed created original](../../verification/2026-10-28-writer-synthetic-create-unknown.md).
4. Linux Unix-domain `SO_PEERCRED` yields kernel peer credentials for a connected peer; filesystem socket permissions and trusted ancestor directories remain separate. UID proves the local process identity in its namespace, not human presence or approval of a specific action. [unix(7)](https://man7.org/linux/man-pages/man7/unix.7.html). The existing [brake authority](../../../../../clean-room/crates/watchdog/src/brake_authority.rs) authenticates bounded requests and delegates opaque targets; its [policy](../../../../../clean-room/crates/watchdog/src/lib.rs#L74) explicitly requires a **non-root** service UID, so it cannot simply be run as root unchanged.
5. [Broker](../../../../../clean-room/crates/watchdog/src/broker.rs#L1) is an unregistered trusted-launch seam, not a production daemon; its `Registry` closes in-process family admission but does not itself persist a root-owned cross-restart authority. The [Batch fixture](../../../../../clean-room/tests/fixtures/docker_batch_guardian.py#L142) durably records intents and closes admission but is Python/test-scoped and relies on Docker for its existing cleanup. The [control-plane entrypoint](../../../../../clean-room/crates/control-plane/src/main.rs#L110) registers only the workflow and budget diagnostic objects; the peer gate is explicitly [experimental](../../../../../clean-room/crates/control-plane/src/atomic_peer_gate.rs#L1). None constitutes the requested installed supervisor.

## Options and recommendation

**Recommend a systemd-managed, minimal root supervisor outside Docker, with root-owned persistent catalog and cgroup ownership, plus a separate unprivileged authenticated brake frontend.** Use fixed systemd service/socket identities and task slices; resolve opaque, one-use IDs against server-owned immutable specs. Never accept a model-chosen executable, PID, cgroup path, mounts or Docker arguments. A protected root helper must independently verify the frontend's peer identity and scope; the current non-root `BrakePolicy` cannot provide that root authority by configuration alone. Keep operator access separate and do not silently provision an SSH key. The user-selected operator/action approval contract is distinct from emergency stop.

A custom root process without systemd could implement the same kernel controls, but loses the existing manager lifecycle and requires its own independent restart mechanism. Docker-only fixture continuation retains the daemon and owner process as a common dependency for cleanup, so it cannot establish the requested independent brake. Transient systemd units are useful for workload subdivision, but neither unit creation nor Docker's cgroup-parent flag alone proves complete containment or closure after a timed-out start.

## Discriminating proof gaps

- Before accepting a late-start guarantee, use a **new owned** task slice and controlled blocked Docker create/start. Persist closure, request freeze, verify the same cgroup inode and `frozen 1`, release the blocked RPC, and test whether the proposed workload can perform a preselected external observable action before freeze applies. Test start-before-freeze, freeze-before-start, child creation and namespace/cgroup movement. A zero `populated` snapshot alone is not a fence against a future accepted start. Retain frozen/closed state on uncertainty.
- Kill and restart only the new supervisor unit during pending create, pending start, and completed stop; verify persistent intent/closure causes startup refusal and that an independent root-owned stop endpoint can still freeze/kill/observe without Docker, Restate, gateway or the workload owner. Test daemon-unavailable through an owned endpoint fault or suspended fixture path; do not restart shared Docker. Full Docker daemon crash, systemd manager loss and host reboot recovery remain unproved without their own controlled maintenance experiment.
- Test peer UID spoofing and same-UID threat assumptions, root-owned catalog/path replacement and symlinks, duplicate action IDs, interrupted fsync and conflicting scope. Socket authentication must precede request body processing and include bounded connection/body limits. An installed root socket's absence of a public listener does not prove catalog provenance.
- Preserve the existing exact-name created container and previous unknowns. A same-daemon name fence is conditional, not a reboot or daemon-replacement proof. Do not clear it to demonstrate an unrelated successful run.

## Minimal integration sequence

1. Inventory proposed factory-prefixed UID/GIDs, root directories, socket, slice and unit names; reject collisions and partial state. Pin installed binary and trusted manifest; make rollback remove only resources proved created by this installation. The user has authorized scoped administration, not a new operator login key or changes to shared deployments.
2. Implement the supervisor as one small owned service with immutable catalog, durable one-way admission closure, explicit unknown state and inode-bound subtree operations. Adapt the existing non-root brake frontend to call a narrow root-owned backend; do not weaken `BrakePolicy`'s identity exclusions or register generic Docker authority. Run the late-start and restart discriminators above before opening the admission path.
3. Connect the already implemented private intake/worker adapter and journal authority to the **same** task/lease identity and the supervisor's single-use launch, with task/attempt/result provenance. Reuse the worker adapter and `StopAuthority` seams; do not create parallel budget or claim authorities. Existing Restate feature bindings must be deliberately migrated and privately provisioned before use; verify lost acknowledgement and retained-state recovery.
4. Connect the pinned Goose/gateway and isolated wall via that launch and receipt path, then the existing exact-revision, action-bound promotion path. Keep first promotion pending the separate human action. A successful one-task live fixture and scoped uncapped budget override do not close production authority, normal budget rules, or the full INT-LOOP.

The evidence supports a bounded implementation and decisive canaries, not a claim of complete supervisor, host-loss recovery, or production readiness.
