# Brake caller amendment: operations research

2026-10-29. This is research, not an adoption or deployment decision.

`clean-room/crates/watchdog/src/lib.rs:83` requires the ordinary operator, generator and evaluator UIDs to be distinct from the brake caller and watchdog. The current frontend draft (`sfactory_brake_frontend.rs:123`) must not omit the operator merely to satisfy the constructor. O4 and the local [evidence ledger](evidence-ledger.md) accept bo as the human operator, exclude MFA and full bo-account-compromise claims, and require independent stop credentials; bo's existing Docker access is host-root authority. R9 also calls for operation when ordinary services and Docker are unavailable.

**A: fixed setuid client, separate brake-caller UID.** This preserves the existing policy and can offer a noninteractive fixed command, but adds a privileged executable and a locked account. Linux preserves supplementary groups across exec, so the helper must explicitly clear them while privileged, close inherited descriptors, authenticate the real caller, drop all real/effective/saved IDs and capabilities permanently, then connect to a fixed endpoint. It must not accept arbitrary paths, commands or environment. Setuid behavior is affected by no-new-privileges and mount settings and all errors must deny; verify actual packaging and launch rather than assume. Sources: [Linux credentials](https://man7.org/linux/man-pages/man7/credentials.7.html), [setgroups](https://man7.org/linux/man-pages/man2/setgroups.2.html), [execve](https://man7.org/linux/man-pages/man2/execve.2.html). A caller able to invoke a client that automatically reads its brake secret can stop; separation from theft of an operator bearer is not separation from compromise of the whole bo account.

**B: explicitly separate production policy with bo as caller.** This avoids another privileged launcher. It cannot honestly use the existing `BrakePolicy` contract; a new named policy requires decision and tests proving independent bearer and service availability. A stolen operator bearer alone must fail, but any user able to read the brake secret and use bo's UID can stop. This may meet O4's scoped exclusions but whether it meets R9's independent credential custody is not established merely by using a second file. Keep existing policy unchanged.

**C: polkit/systemd broker.** Systemd's D-Bus unit-management authorization covers operations including starting and stopping units; a generic grant is too broad. Polkit is a separate authority and may require a session authentication agent, so a headless noninteractive path and strict action, unit and verb constraints must be demonstrated rather than inferred. Sources: [systemd manager API](https://www.freedesktop.org/software/systemd/man/257/org.freedesktop.systemd1.html), [polkit architecture](https://polkit.pages.freedesktop.org/polkit/polkit.8.html). A dedicated fixed broker reduces exposed verbs but still adds a privileged service and its recovery dependency.

The current evidence favors evaluating A first because it retains the existing explicit UID separation while limiting operations to one client. It is not yet selected: verify actual stop-key custody, supplementary-group and UID dropping, wrong caller/key/target denial, no arbitrary execution, clean environment/FDs, and independent stop under control/database/gateway/Docker outage. Review B against R9's actual custody requirement and C against exact installed policy before deciding. No privileged client or policy was installed by this research.
