# Root launch grant contract — draft, not deployed

The root supervisor must not authorize from `ClaimLeaseJournal.status`: it is a stored snapshot, not a current lease-validity assertion. The worker socket admits the configured worker UID, not root. A separate root-created `/run/software-factory-goose/launch-grant.sock` with root:root 0600 and a fixed service handler accepting only kernel peer UID 0 is the proposed narrow request channel. The client must verify its root-owned pathname/ancestors, activated listener's kernel peer identity, and immutable deployment binding. No model or worker receives access. This contract is not implemented or accepted.

The root request selects only the preauthorized opaque generation; the private service resolves the root-owned immutable catalog instead of trusting a caller-supplied recipe, task, paths, or lease. The catalog must bind exact intent, task, queue, repository, base revision, task inputs and evidence digest, generation, worker, execution recipe and deadline policy. The single exclusive `ClaimLeaseJournal` handler obtains its own active lease, verifies its worker, attempt and token, validates journal time against issued/expiry/hard deadline, and atomically stores `LaunchReserved` before returning an exact scope-bound grant. The candidate scope binds intent and queue explicitly and uses the complete qualified catalog fingerprint. The root endpoint and runtime candidate remain uninstalled until reviewed. A change to catalog or immutable fields must reject rather than create another grant. Lost acknowledgements may return the same persisted grant only while still valid; no new attempt or reset follows a transport timeout.

The root supervisor verifies the peer, full immutable catalog binding, grant identity, attempt, token digest and deadlines; it fsyncs single-use consumption and root generation intent before any engine effect. Duplicate, changed, expired, unauthenticated, unknown, or ambiguous requests are denied, with no alternate worker-facing route. Root admission must arm an independently owned stop timer before the first possible engine effect. Any unknown dispatch is retained and never automatically replayed. The timer freezes/closes the exact cgroup generation on deadline, including when the control service, journal, ordinary launch lock, or Docker is unavailable. A wall-clock rollback, restart, reboot, missing timer or uncertain identity must fail closed; neither process restart nor absence of a status response can reopen a reservation.

A journal reservation remains durable and blocks new claims, renewals and completions after expiry, revocation or failure. A future authenticated root closure-and-engine-reconciliation receipt must bind the exact grant, generation, cgroup identity, boot identity and final closed/frozen/empty/engine outcome before any journal transition clears it. The receipt verifier and clear operation do not yet exist. Until they do, the reservation deliberately sacrifices availability. An empty cgroup sample by itself is not proof that a delayed engine start cannot occur, and a journal lease expiry by itself is not a stop receipt.

Required tests: actual distinct UID and root socket peers; forged task/generation/catalog/proof and stale lease; same-grant lost acknowledgement and duplicate consumption; changed scope; expiry racing begin; timer and stop during held launcher RPC; missing service or journal; owner loss, restart and boot identity change; delayed Docker start and reconciliation; and zero engine effects for every denied or uncertain pre-begin request. Compare exact journal and root receipts across restart and prove no implicit regrant. Until these pass, keep root launcher admission closed and do not claim an integrated runtime or promotion.
