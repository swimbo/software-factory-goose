# Independent application-security position

Final position after revised-A review: **recommend revised A conditionally; reject C and do not adopt B as the callback fix**. The initial B recommendation below is superseded by the ownership design and acceptance conditions here. This is a source review, not adoption or integration approval; no services, model calls or deployment were performed.

## Authority and capability boundary

`sfactory_root_launch.rs` accepts one canonical generation, loads a root catalogue and verified grant, hashes a protected helper, and executes only five fixed phases through an environment-clearing runner. `root_grant.rs` checks catalogue ancestors, ownership, ACLs, recipe pins and grant/deadline binding. `root-launch-host.py` fixes Docker arguments and images, checks manager properties and full container IDs, preserves intent/unknown state, and independently rechecks closure/deadline. I found no caller-supplied arbitrary command/path/env execution surface in these files.

A cap-empty root process with access to the root Docker API is already in the host-root trusted base. B expands its *direct* kernel authority to host-wide DAC read/search bypass, not merely these two directories. That matters for accidental disclosure and confused-deputy bugs, even though a fully compromised launcher could already use Docker for host-root access. Do not describe either A or B as sandboxing this launcher.

Linux documents that CAP_DAC_READ_SEARCH also enables `open_by_handle_at` and `linkat(AT_EMPTY_PATH)`. It does not generally bypass write permission or ptrace checks. NNP prevents acquiring new privilege through exec; it does not revoke existing/ambient capabilities. systemd 257 ambient capabilities propagate through ordinary exec and augment the inheritable set. Therefore the Python helper and its ordinary CLI descendants can inherit B; “only launcher” must mean the entire fixed launch process tree, never the separately manager-started worker/relay/broker/brake. Verify this explicitly rather than assume environment clearing drops capabilities. Sources: [Linux capabilities](https://man7.org/linux/man-pages/man7/capabilities.7.html), [systemd 257 execution settings](https://www.freedesktop.org/software/systemd/man/257/systemd.exec.html#Capabilities).

## Concrete boundary gaps

1. **Callback pathname check/use race.** `validate_inputs()` checks a UID2000-owned 0700 directory and a root-owned socket, then closes descriptors. `docker_args()` subsequently supplies its pathname for Docker to resolve. Directory owner UID2000 can unlink/rename a root-owned child without owning that child. `secure_socket()` and Docker mount inspection do not pin the socket inode to the checked object. A compromised relay can race socket substitution, causing mount misbinding or denial of service; a useful substitute additionally depends on target socket permissions/protocol. I have not proved host-root escape. This is pre-existing, not created by B. If UID2000 is outside the trusted base, require a root-controlled callback parent or a tested stable mount/descriptor handoff before treating callback identity as an enforced security boundary. O_NOFOLLOW on a checked directory does not pin a subsequent pathname lookup.
2. **Process metadata remains a separate permission boundary.** DAC_READ_SEARCH is not CAP_SYS_PTRACE. `/proc/<pid>/ns/net` or equivalent ptrace-gated metadata may still fail despite the private-directory probe succeeding. Do not solve that with C: redesign attestation around manager/kernel evidence or fail closed.
3. **Probe is narrower than launch readiness.** `nuc_real_launch_access_probe.py` checks only CapEff=0/4, NNP and two directory opens. It does not establish exact permitted/inheritable/bounding/ambient sets, helper execution, mount identity, registry/process attestation or independent braking. The referenced `/tmp/sfactory-identity-admin-1pdillk2` receipt is absent in this checkout; its reported success is supplied evidence, not independently inspected here. The original launch failure remains unattributed because stderr was discarded.

## Conditions before B adoption

Require exact native capability/NNP and manager configuration receipts; successful bounded read-only verification of the real fixed helper, all inputs and ptrace-sensitive attestations in that context; a threat-model decision or fix for UID2000 callback substitution; and independent active brake/deadline plus late-start/unknown-outcome fencing. Keep the failed generation permanently closed. These checks authorize no fresh provider dispatch.

A should use root-owned immutable publication paths or descriptor handoff rather than weakening private directory modes, adding worker groups or sharing capability with workers. B is the smaller immediate access amendment only if these conditions pass; neither option establishes daemon/host-loss recovery or human-presence/MFA.


## Final consensus on revised A

Agree with operations and contrarian: root:2000/0710 callback ownership closes UID2000 child replacement authority and lets cap-empty root inspect the callback. Keep the separate UID2000/0700 fence private; it is not a launcher input. UID2000 gets search for O_PATH/stat/inherited-listener validation, not listing or mutation. UID2001 denial must test child lookup/connect with actual supplementary groups; opening the parent itself with O_PATH is not a sufficient negative control.

Conditional acceptance requires coherent changes to creation, helper and relay validation plus every installed hash/manifest/pin; protected ancestors with no ACL grants; exact zero E/P/I/B/A capabilities and NNP=1 in native launcher/descendants; successful actual helper/input/unit/registry/process preflight; UID2000 positive validation and mutation denials; and UID2001 host child traversal/connect denial. These are unrun acceptance requirements, not claims of success.

Trusted socket-unit stop/rebind must be excluded across validation through Docker create, with socket device/inode identity rechecked around create and fail-closed handling of any mismatch. Merely rechecking pathname strings or observing equal before/after inodes without lifecycle exclusion does not exclude an intermediate substitution. Root/Docker administrators remain trusted; this does not certify a race-free boundary against them.

Use root-owned versioned byte/metadata backups and a durable admission barrier over the entire helper/package/manifest closure. Per-file atomic rename alone is insufficient. Interrupted transitions remain fenced until all pins and installed bytes reconcile; rollback must never restore consumed grant/deadline/closure authority. Leave shared running services and closed generations unchanged. Retain independent brake/deadline, unknown-outcome and late-start gates. No further security objection to this bounded revised-A plan, subject to local review and full post-change proof before any adoption or separately authorized launch.
