# Application-security research: root-attested finalization

## Recommendation

Choose additive root-only finalization on the existing exclusive claim object. Preserve the permanent launch reservation and legacy claim/projection unchanged, including unknown spend. This is a proposal for a narrowly scoped implementation and disposable verification, not evidence that an operational root finalizer, authenticated evaluator, exclusive ingress, or production registration exists. Do not authorize promotion or a fresh launch from this record.

## Evidence and security implications

1. The current [reservation contract](../../../../../clean-room/crates/control-plane/src/launch_reservation.rs) binds task, generation, immutable spec, worker, catalog digest, attempt and lease-token hash. `allow_mutation` denies whenever a reservation exists, without clearing it on expiry. The [claim handlers](../../../../../clean-room/crates/control-plane/src/workflow.rs) call this guard for initialize, claim, renew and worker complete. An additive handler must not call worker completion or erase that reservation.
2. `ClaimLeaseJournal` uses `ObjectContext` for the reserving and mutating handlers. The [Restate Rust SDK documentation](https://docs.rs/restate-sdk/0.12.1/restate_sdk/) describes exclusive object state access and distinguishes shared read-only handlers. Thus an exclusive finalizer keyed to the same object can serialize comparison against the reservation and claim; this is contingent on actually invoking the same registered object/key and protecting all routes to it. A separate service or object cannot inherit this lock.
3. The [root grant adapter](../../../../../clean-room/crates/control-plane/src/root_launch_grant.rs) obtains the accepted Unix peer UID from kernel credentials before processing request data and constructs a fixed backend URL from server-owned scope. Linux [unix(7)](https://man7.org/linux/man-pages/man7/unix.7.html) specifies `SO_PEERCRED` credentials reflect the peer at connection/listen/socketpair time. UID 0 is not itself an application identity or proof of the process serving an inherited systemd socket: require independent root-owned post-start service attestation and prohibit untrusted direct access to the private Restate ingress.
4. The legacy [receipt](../../../../../clean-room/crates/shared/src/lib.rs) and [projection](../../../../../clean-room/crates/control-plane/src/projection.rs) encode completed spend as a finite nonnegative number and associate evaluating with a completed receipt. The uncapped experiment lacks verified total routed and classifier costs. Substituting zero, a guessed amount, or a legacy completion would manufacture a fact and contaminate projection; the new status must represent unknown separately.
5. Exact cleanup and evaluation cannot be inferred from a worker's message, cgroup emptiness alone, an acknowledged stop, or a digest supplied by the caller. Root must establish both exact container identities absent, terminal create/start and nonrestartable relay/broker jobs, boot/inode-matched closed empty cgroup, and independent evaluation of exact immutable candidate/committed blobs. Root-owned evidence must be protected at open/read time, including symlink, hard-link, ownership, mode and ACL checks; root/daemon compromise remains outside the stated trust boundary. [Contract draft](contract-draft.md).
6. Durable replay does not make an external action exactly once. The official [Restate durable-execution overview](https://docs.restate.dev/ai/patterns/multi-agent) describes journalled execution and recovery; the official [example](https://github.com/restatedev/examples/blob/main/typescript/patterns-use-cases/src/database/main.ts) explains a database effect can occur before its completion is observed. The finalization handler should perform no external cleanup or provider effect: validate already obtained evidence, journal immutable decision and outbox together, and prove lost-ack replay. Do not infer atomicity with Postgres or external Docker from the object lock.

## Options

| Option | Assessment |
| --- | --- |
| Add root-only finalization and independent typed status | Preferred. Keeps the existing fence and legacy state semantics, isolates unknown spend, and admits exact replay only for identical root evidence. Requires trusted socket, ingress and evidence producer. |
| Reuse worker `complete`, remove or bypass fence | Reject. Worker-origin authority cannot establish root cleanup/evaluator provenance; an expiry or retry could reopen execution and falsely declare reconciliation. |
| Migrate legacy completion/schema now | Defer. A reviewed migration could eventually represent unknown spend and connect the pipeline, but it expands legacy state, projection and replay risks before root evidence is proven. |
| Leave reserved forever without finalization | Safe but loses durable outcome visibility; appropriate if any evidence or root identity is uncertain. |

## Required controls and unresolved evidence

- **Authority:** verify root on the accepted socket before bounded body reads; fixed root catalog selects task/generation and no caller path, proof, result or candidate. Independently attest the serving process after systemd startup. Protect journal ingress so a worker or network peer cannot call the new SDK handler directly; a socket check does not secure a separately reachable backend.
- **Exact binding:** compare canonical full stored reservation and active claim, including task, generation, attempt, repository, baseline, catalog/root-grant digest and lease-token hash. Check the retained reservation after lease expiry without issuing a new claim or requiring that its expired lease is live. Fail closed on missing, substituted or unvalidated proof. Unknown finalization is never a pass.
- **Evidence provenance:** define deterministic, versioned evidence records and digests; open protected inputs descriptor-relative, enforce owner/mode/single-link/no ACL, and pin identities across reads. Bind boot, cgroup inode, close/deadline, both root IDs and terminal operation receipts, plus actual candidate hashes, evaluator authority and committed blob verification. Durability and immutability of those actual producers are not established by this draft.
- **Replay and publication:** same exclusive handler must commit one immutable status and monotonic outbox record with deterministic duplicate handling. Identical repeat returns the same record; every changed binding/evidence or preexisting contradictory record denies. Verify actual journal/outbox persistence and delivery recovery rather than claiming cross-system atomicity. Preserve original reservation and unknown actual spend.
- **Tests:** disposable Restate and Postgres, non-root and wrong-peer connections before body read, direct-ingress denial, no reservation, wrong task/generation/attempt/catalog, expiry, changed evidence, forged evaluator/closure, in-flight create/start and restartable services, missing root evidence, lost acknowledgement and restart, exact versus changed replay. Prove the old original, grant-canary and real-catalog histories remain readable through a distinct deployment URI without force registration; no external effects should repeat.

No existing source shown here proves the proposed finalization handler or its root-only deployment. The evaluator producer, exclusive private ingress, process attestation, exact Docker reconciliation and independent timeout/closure authority remain explicit prerequisites. The later migration and human action-bound promotion are separate decisions.
