# Comparative containment spike

**Status: proposed; production design not selected.** Start with reversible, unprivileged experiments and inspection of task-owned resources. Do not provision accounts or privileged services, alter existing engines, or start an existing VM. If a test requires these changes, prepare a concrete isolated fixture and seek the required authorization first.

1. Establish a positive and negative baseline for the existing group broker, including an owned child that calls `setsid`, a blocked launch, and cleanup without signaling an unowned or reused PID. This is a falsification fixture, not a new runtime.
2. Inventory whether an owned disposable Linux boot image, isolated VM runner, entitlement and host control are available. Check presence and provenance without reading secrets or touching existing VMs. Record missing prerequisites; do not infer support from `kern.hv_support`.
3. If prerequisites permit an isolated VM fixture, use a fresh temporary disk, no host mounts or credentials, restricted networking and a synthetic workload. Verify actual guest boot, `setsid`/double-fork escape, stop of a suspended guest workload and independently observed execution cessation. Run negative controls for unauthorized stop, host access and direct network egress.
4. Test the host owner paused and killed before and after acceptance, including a stop during blocked launch. Verify independent stop availability and VM absence or halted state from a trustworthy authority. On restart, refuse ambiguous outcomes and duplicate launch; never signal a persisted numeric PID. If no independent owner/control exists, record a failure rather than treating an API call as termination.
5. Compare startup and recovery costs with a native privileged supervisor only if a specific, verifiable native containment primitive exists. A separate-UID fixture must verify actual credentials, supplementary groups, access denials, signaling, and orphan handling. Preserve the independent stop-only principal and keep command admission opaque and immutable.
6. Record exact image/binary provenance, positive and negative observations, cleanup, and remaining unknowns. Return to the decision review only when the facts can support a choice; do not activate the worker or claim INT-LOOP completion on a spike.
