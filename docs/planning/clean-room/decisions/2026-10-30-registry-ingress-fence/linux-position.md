# Linux position: test Unix admin and old-SDK retirement first

I recommend one bounded, disposable Restate 1.8.0 spike using the installed pinned executable, a fresh task-owned data directory, and two synthetic SDKs. Test per-service Unix-only admin plus retirement of the old SDK listener. This is the most discriminating next step because the pinned source has service-level listen options, while the running NUC currently uses TCP and no actual socket-mode or restart behavior has been proved. If the exact binary cannot isolate admin without disturbing the ingress required by SDK5, or cannot enforce its socket permissions, reject this direction and assess namespace-local firewalling instead. This is a conditional implementation direction, not permission to restart the existing journal or production acceptance. [Pinned 1.8.0 listener options](https://github.com/restatedev/restate/blob/v1.8.0/crates/types/src/config/common.rs), [pinned admin options](https://github.com/restatedev/restate/blob/v1.8.0/crates/types/src/config/admin.rs), [NUC findings](linux-research.md).

The design has four separate boundaries:

1. **Admin 9070.** The disposable server must show that admin is available only on a protected pathname socket, with TCP 9070 absent and UID2000 unable to connect. A root-owned fixed operation can use the admin socket; it must not offer caller-selected HTTP paths, deployment URIs, SQL, descriptors or commands. Root, PID1, the daemon and UID2004 are trusted by the agreed model. This does not assert resistance to a compromised root or journal account. The actual socket path, parent ownership, mode, absence of permissive ACLs, open descriptors and behavior after restart all need observed evidence. Self-hosted Restate documents no application authentication on management interfaces; loopback alone does not separate two local UIDs. [Restate server security](https://docs.restate.dev/server/security), [unix(7)](https://man7.org/linux/man-pages/man7/unix.7.html).
2. **Direct same-UID old SDK access.** A root-owned retirement protocol must stop every exact ungated SDK service and its socket activation path, prove its main process and control group terminal with no pending job, preserve its unit definition, and enforce no subsequent start before completing the transition. SDK1–4 are currently active; fencing SDK4 alone leaves three older endpoints. Since their listeners and the new SDK use UID2000, `meta skuid` cannot distinguish a malicious or accidental same-UID direct call from another UID2000 process. The fixture must attempt a direct call before and after retirement and verify an explicit mutation marker. Exact manager unit, listener and restart semantics matter: `disable` is not `mask`, and a local unit may prevent a simple mask. [systemctl 257](https://www.freedesktop.org/software/systemd/man/257/systemctl.html), [systemd.kill 257](https://www.freedesktop.org/software/systemd/man/257/systemd.kill.html).
3. **8080 forwarding.** Disabling admin and blocking direct old ports does not stop UID2000 submitting an old-target invocation on Restate ingress 8080, which Restate UID2004 can forward to the old SDK. The spike must first show the mutation succeeds through this route, then show the chosen transition denies execution after old endpoint retirement. During transition, fixed producer admission and registration are closed; any work accepted by 8080 remains recorded and cannot be treated as completed merely because the endpoint is unavailable. New SDK5 registration must not make an old pinned invocation run old code or silently migrate it. Restate documents pinning for in-flight work; the pinned-binary experiment must verify this precise scenario. [Restate versioning](https://docs.restate.dev/services/versioning).
4. **Old queued and in-flight work.** Record exact deployment IDs and positive controls for running, queued, scheduled, suspended and unpinned work. Show how each appears in `sys_invocation_status`, `sys_vqueues`, and `sys_vqueue_entry_status` on the pinned binary. Enumerate retained work before and after the fence; distinguish terminal, pending, unpinned and ambiguous. Hold transition closed for an unknown effect or a still-executable old mutation. If a pinned invocation becomes unavailable because its old SDK was retired, report it explicitly and retain its journal and deployment; do not call it drained, erase it, or dispatch it again. The actual schema receipt establishes column names only. [NUC schema evidence](linux-research.md), [Restate v1.8.0 release history](https://github.com/restatedev/restate/blob/v1.8.0/release-notes/v1.7.4.md).

The canary must be genuinely owned: fresh data and namespace, uniquely named bounded units, prewritten durable intent, full unit/process/socket identities and no shared mounts or credentials. Exercise an allowed fixed broker request and negative UID2000 and UID2001 requests. Test accidental inheritance and SCM_RIGHTS leakage of already-open privileged descriptors; do not make compromise of trusted root or PID1 the acceptance criterion. Confirm unrelated benign TCP ingress and Postgres-equivalent traffic still work. Kill only task-owned controllers at defined points, check that pending state fails closed, and test server and manager restart using only disposable resources. Runtime 1.8.0 per-service configuration must be inspected on the running canary; its global `--listen-mode` help alone is insufficient.

I do not recommend making a live UID firewall the first experiment. It can be a fallback if the Unix-admin canary fails, or an additional hardening layer after explicit selection. A rule that denies UID2000 access to 9070 and 9084 while leaving 8080 and Restate UID2004 forwarding open has a concrete route around it. Socket UID tracks the originating socket, so old connections and descriptors passed by a trusted process also require tests. Firewall state belongs to the network namespace and can disappear on replacement; the current private anchor has an empty capability bounding set, so an operational policy would need a separately provisioned authority and monitoring. [nftables socket UID](https://wiki.nftables.org/wiki-nftables/index.php/Matching_packet_metainformation), [network_namespaces(7)](https://man7.org/linux/man-pages/man7/network_namespaces.7.html).

No SQL zero or success receipt can substitute for the independent fence. For a later reviewed deployment, fsync the transition marker under the exclusive root lock before effects; bind boot, namespace, unit, socket, manifest and deployment identities. Capture prior history, close old producers and endpoints, establish safe old-work classification, register SDK5 exactly once, persist the server-minted ID, attest the new process, and replay every prior history. Recheck the admin and endpoint fences immediately before releasing the marker. A lost acknowledgment, unknown effect, changed identity, unexpected successful old mutation or missing old-work classification keeps it closed.

Fixture cleanup removes only the exact owned units, socket, data and namespace after terminal confirmation. For a later live operation, an ambiguous partial change retains its intent and all state for explicit recovery; do not blindly restart old ungated SDKs after new admission or clear the marker. A real Restate restart, firewall policy, rollback or activation remains subject to its own reviewed concrete plan.
