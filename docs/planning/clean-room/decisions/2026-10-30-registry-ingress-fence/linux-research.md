# Linux networking research

Research only, 2026-10-30. No host networking, account, service, socket or firewall changes. The goal is to prevent ungated SDK calls and unauthorized Restate administration during a registry transition while preserving the journal; no option has yet passed a production proof.

## Evidence

1. Self-hosted Restate says management interfaces have no built-in application authentication, and 9070 needs trusted-operator network restrictions. Its request identity feature authenticates Restate-to-service calls, not clients of the admin API. Current NUC Restate is version 1.8.0 and runs `--listen-mode tcp`; its own `--help` lists `unix`, `tcp`, and `all`. Current Restate documentation describes per-service `admin.listen-mode = "unix"`, but this exact per-service setting, path, permissions and upgrade/restart behavior have not yet been verified on the pinned binary. [Server security](https://docs.restate.dev/server/security); [network configuration](https://docs.restate.dev/server/networking).
2. PID1 read-only inventory shows private Restate UID2004 PID 418551, Postgres UID2004 PID 418536, and SDK1–4 UID2000 PIDs 424877, 527482, 561251, 630199 active in the private network namespace; SDK5 is inactive. The SDKs use 9081–9084, respectively, and SDK5 is 9085. Runtime ingress uses 8080 and Postgres 55432. Existing UID2000 registration, inventory and replay probes use admin 9070. This is unit/source inventory, not proof of every established connection or every inherited file descriptor.
3. Linux network namespaces isolate port numbers, network stacks and firewall rules; namespace loss destroys its rules. The NUC anchor is root PID 418529 with `CapabilityBoundingSet=` and `NoNewPrivileges=yes`; `nft` and `iptables` binaries exist, but we have not established authority to alter this namespace. Administering firewall state requires the relevant `CAP_NET_ADMIN` in the owning user/network namespace. A separate privileged task canary is needed; neither installed binaries nor UID0 prove it. [network_namespaces(7)](https://man7.org/linux/man-pages/man7/network_namespaces.7.html); [capabilities(7)](https://man7.org/linux/man-pages/man7/capabilities.7.html).
4. nftables `meta skuid` identifies the **originating socket's** UID. It does not attest the process currently writing. SCM_RIGHTS transfers a reference to an existing open file description; an already-open privileged connection can be inherited or passed. Rules, namespace mappings, established sockets and descriptor transfer must be exercised, not assumed. A filter should not automatically accept `ct state established` before the deny check. [nftables UID match](https://wiki.nftables.org/wiki-nftables/index.php/Matching_packet_metainformation); [unix(7)](https://man7.org/linux/man-pages/man7/unix.7.html).
5. Linux pathname UNIX socket connection honors directory traversal and socket write permissions, but abstract sockets do not honor filesystem mode. A root-owned peer-checking broker can narrow the interface only if the underlying admin socket is inaccessible to UID2000, inherited/passed connections are excluded, and the broker cannot act on arbitrary caller commands. Systemd socket activation is not an automatic close barrier: manager-held sockets and already accepted connections require explicit handling. [unix(7)](https://man7.org/linux/man-pages/man7/unix.7.html); [systemd.socket(5)](https://man7.org/linux/man-pages/man5/systemd.socket.5.html).
6. Pinned Restate 1.8.0's observed SQL schema includes `sys_invocation_status.pinned_deployment_id` and `deployment` in both `sys_vqueues` and `sys_vqueue_entry_status` (root receipt `/tmp/sfactory-identity-admin-8mdevoh2`). Upstream's [1.7.4 release notes](https://github.com/restatedev/restate/blob/main/release-notes/v1.7.4.md) describe a correction to queue deployment visibility. These fields do not prevent a new invocation after a query, and a NULL deployment may indicate queued or not-yet-pinned work. Positive controls on the exact pinned runtime remain required.

## Options and proof gaps

| Option | What can enforce | Operational cost and gaps |
|---|---|---|
| Per-service private Unix admin + root broker; retire old ungated SDKs | A protected pathname and fixed broker can isolate registration from UID2000; retiring old listeners prevents direct access to their unguarded code | Requires a reviewed Restate configuration change/restart, verified 1.8.0 socket path/permissions and all existing admin client migrations. Stop/mask exact old socket units and services only after no-job/process/FD/invocation evidence; retain old deployment histories and unresolved invocations. Tests must establish manager won't reactivate old endpoints and show safe handling of unavailable old pinned work. |
| Private-net nft output policy + root broker; retain SDK4 while draining | Kernel can distinguish socket owner when packets leave local namespace; Restate UID2004 can potentially reach 9084 while UID2000 cannot | Adds CAP_NET_ADMIN/namespace authority and live shared-namespace rules. Existing trusted probes using UID2000:9070 must move. Need IPv4/IPv6, existing/passed sockets, response direction, namespaces, ruleset identity, restart and direct access to all old endpoints. A policy on 9070/9084 alone leaves other ungated SDK endpoints and 8080 invocation ingress open. |
| Stop/mask SDK4 only | Closes that process/listener if manager and all descriptor owners are accounted for | Does not protect admin 9070, the other active ungated SDKs, or earlier revisions still pinned in Restate. A stop is a containment step; it is not proof that queued invocations completed. |
| New handler flock and SQL snapshot only | Fences new SDK5 code participating in the lock | Cannot constrain already running old code or a new old-directed HTTP request. Reject as sufficient. |

## Minimal discriminating canary

Use a **new** uniquely named disposable network namespace, synthetic service ports and task-owned processes. Separate trusted server UID2004 and caller UID2000; inspect exact namespace inode/ruleset and reserve and fsync intent first. Confirm a positive no-policy request, then test a narrow output rule with counters: new denied UID2000 connections, pre-established UID2000 connections, a UID2004-opened descriptor passed to UID2000, traffic in both directions and IPv4/IPv6. Verify allowed UID2004-to-service and unrelated traffic. Include user-namespace UID mapping, policy process death and namespace teardown/recreation, and a control showing connection reuse or transferred sockets cannot silently bypass the claimed fence. Exact UID, NNP/capability and unit/namespace properties must be recorded; cleanup removes only fixture-owned resources and retains unknown outcomes. This establishes only Linux behavior on the fixture.

In parallel, start a **disposable copy** of the pinned Restate binary with a fresh data directory, per-service Unix-only admin and fixed protected socket parent. Check actual bind path, owner/mode, direct TCP refusal, UID2000 denial and permitted fixed broker operation, including old existing descriptor and restart cases. Create synthetic invocations pinned to old and new SDKs to demonstrate query and retirement behavior; avoid real journal or services. Compare the extra Restate restart/proxy and identity requirements against nft privilege and shared rules. Current evidence supports neither production cutover nor a selection yet.

If later adopted, a root transition must fsync intent, freeze admission, protect the exact selected namespace/endpoint and descriptor set, drain/fence all old revisions, perform one non-force registration and bind its actual returned ID, verify process/boot/namespace identities, replay exact historical state, publish durable completion and only then reopen. Crashes, unknown registration or inconclusive drain retain the marker and must not silently roll back to an ungated live SDK. No inference or candidate promotion follows from this research.
