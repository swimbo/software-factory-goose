# Production private Restate transition: review draft

This is a proposed one-shot transition, not permission to execute it. The SDK1–4 retirement/replay and Unix-admin integration spike must first pass its complete gates. No production process, configuration, journal, database or account is changed by this document. If the spike cannot establish the chosen fence, retain the failure and revise this plan.

The existing Restate executable is `/usr/local/libexec/software-factory-goose/private-restate`, pinned SHA-256 `a45eba5044e331636b9da5a8f37fc901dec4cd3ccfcb10889241f76fe9c209db`; the current owned unit is `software-factory-goose-private-restate.service`, base directory `/var/lib/software-factory-goose/journal/restate`, node `sfgoose-private`. The proposed config adds a root-owned fixed file containing `listen-mode = "tcp"` and `[admin]\nlisten-mode = "unix"`, with the same pinned binary, base directory, node, loopback bind and nonrandom ports. Exact config path, socket pathname, drop-in bytes, modes, source SHA, unit/cgroup identity and PID1 properties must be derived from the passing spike and fixed in a reviewable PLAN. The private ingress TCP listener remains required. Never fall back to TCP administration if Unix-only verification fails.

1. **Read-only baseline.** Under the fixed exclusive registry gate, verify the protected current head, no prior transition marker and exact current boot, private and host namespace identities, anchor/systemd invocations, PG data directory device/inode and `pg_control_system()` identifier, Restate binary/unit/cgroup/process identity, current registry digest, all existing deployment IDs, queued/pinned/delayed invocation and claim/reservation inventory, and every fixed known admin client. Preserve only digests and bounded metadata; do not expose tokens or state bodies. SDK1–4 must be enumerated by exact unit, socket units, process identity, port and deployment ID, including 9081–9084. Unknown clients, ownership, outstanding external work or permissions leave the transition closed. Capture source, binary, unit and metadata hashes in a root-owned create-only plan.
2. **Durable closure and retirement.** With the same exclusive lock, fsync the root-owned transition intent and parent before effects. For each SDK1–4 service and every activation socket, persist a fixed restart-refusal fence before stopping the exact unit/socket. Preserve unit files, binaries and deployment metadata. Verify each intended unit's PID1 identity, no job, inactive process, empty exact cgroup, no listener or surviving serving descriptor, and denied restart; a previously established connection and forwarded request must not execute old code. A service-only stop is insufficient. Any timeout, inconsistent identity or ambiguous fence keeps the marker and all evidence; do not retry, reset, or treat queued work as completed.
3. **Recoverable Restate backup and config cutover.** After closure and terminal proof of the four old endpoints, stop only the exact owned Restate service, establish terminal PID/cgroup and exclusive ownership of its data, and produce a create-only offline backup of the owned Restate base directory in a newly named, access-restricted, durable location. Use an independently reviewed bounded archive/copy method that rejects unsafe file types, symlinks and changing inputs, preserves required metadata, fsyncs data and parent, and records a manifest/digest. Prove recoverability by restoring a copy into a separate disposable namespace/data root and checking pinned Restate starts and the preserved catalog/history is readable; never test by overwriting the real directory. If backup or restore is unproved, stop. Preserve PostgreSQL in place; do not copy a live PG directory or change its service, system identifier, data directory, namespace anchor or cgroup. If a PG backup is later required, use its own tested online-consistent procedure and exact scope.
4. **One Restate restart and Unix proof.** Create the reviewed config and fixed create-only unit override only after the backup receipt, with a durable per-phase intent. Reload systemd and start only the same Restate unit, using the existing data root/node and new config. Compare the new invocation ID and PID against the recorded old identity while proving unchanged boot, namespaces, anchor, PG unit/PID/data inode/system identifier, owned paths and pinned binary. The old Restate PID is expected to differ; no other process may be substituted. Native UID2004/PID1 probes must verify the exact root-protected Unix-admin socket and its owner/mode/ACL, no TCP 9070 listener, UID2000 denial, UID2004 fixed operation allowed, and no admin descriptor inherited by SDK5. On restart/namespace loss, readiness must fail closed. An unknown start or probe keeps the transition pending.
5. **Decisive inventory and one registration.** Recheck every retirement fence and current namespace/process identity before querying through a fixed root-mediated UID2004 admin operation. Count and enumerate old pinned, queued, delayed/unpinned and nonterminal work using the independently tested zero predicate. Retained nonterminal work is unavailable quarantine and blocks ordinary release when effects can overlap; never cancel, delete, force-register, or claim it drained. Only after this check may one fixed non-force SDK5 registration be attempted. Persist its intent before the request and bind the server-minted deployment ID/URI to the exact attempt. A lost response is unknown and cannot be resent.
6. **Replay, prove and admit.** Attest the exact SDK5 serving process, namespace, unit, sockets and immutable catalog; replay every previous catalog's histories through the registered endpoint and compare protected before/after hashes. Verify admin protection, all four retirement fences and no overlapping retained work again. Store independently produced root receipts and versioned transition completion; publish a new registry head only under the still-held lock after all evidence is durably synced. The finalizer's SDK5 receipt verifier remains pinned unavailable until that producer and full native fixture proof exist. Do not activate the finalizer or publish its unknown record during this cutover.

## Versioned baseline and recovery

Existing `old.old_snapshot()` embeds an SDK1 active PID and expects the original Restate PID; it is a pre-transition preservation check and cannot validate this authorized transition. Do not weaken it or silently ignore its failure. Add a separately versioned transition snapshot with exact before/after schema: SDK1–4 may move only from the individually identified active state to their proved retired state; the exact Restate unit may acquire one new PID/invocation for this config change; PG service PID/invocation, cluster system ID and data inode, boot, host/private namespace, anchor and all unrelated factory/shared services must match the baseline. Root receipts must bind both snapshots, the specific actions and the backup digest. Any other delta is a hard failure, not an accepted restart.

Every effect has a create-only durable intent, exact target and separate completion receipt. An ambiguous stop, backup, restart, registration or admission keeps the exclusive transition marker and prior receipts intact. A recovery operation must first inventory the exact current unit, process, cgroup, listener, files and journal state, prove ownership, and have its own reviewed no-retry plan. Rollback is a separate explicit plan from the offline backup; it must preserve all later journal history and must never silently restore over an advanced live journal. No shared Hermes, Bifrost, Stapled or unrelated unit is stopped.
