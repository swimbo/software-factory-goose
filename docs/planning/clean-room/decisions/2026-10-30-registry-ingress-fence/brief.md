# Registry transition ingress fence: decision brief

Status: three-reviewer conditional consensus, 2026-10-30; see [consensus-plan.md](consensus-plan.md). The chosen next step is one disposable pinned Unix-admin/old-SDK-retirement experiment. No live network or service changes have been made or authorized by this brief. A zero-count SQL snapshot is not a fence.

## Current evidence

- NUC's installed `/usr/local/libexec/software-factory-goose/private-restate --version` reports `restate-server 1.8.0`. Its manager unit runs as UID 2004 with TCP loopback in the `software-factory-goose-private-net.service` network namespace. `systemctl show` on 2026-10-30 found private-runtime PID 424877, grant-sidecar PID 527482, real-sidecar PID 561251, and registry SDK4 PID 630199 all active as UID 2000 in that namespace; SDK5 is inactive. These are observations, not an exhaustive connection inventory.
- `/usr/sbin/nft` and `/usr/sbin/iptables` exist. The private namespace anchor is root with an empty capability bounding set and NoNewPrivileges; this establishes neither firewall configuration nor permission to change it.
- Runtime source and the installed registration approach use private Restate ingress 8080, admin 9070 and SDK endpoints 9081–9085. Registration scripts and the history/inspection/schema probes use 9070 from UID 2000; the active runtime also needs 8080, and Postgres uses 55432. Blocking all UID 2000 loopback traffic would break normal operation. Static search is not a complete inventory of existing connections or inherited descriptors.
- Self-hosted Restate documents that its management interface has no application-level authentication and recommends restricting admin access at the network layer or using a Unix socket ([server security](https://docs.restate.dev/server/security)). Its request-identity feature is a different boundary: it authenticates Restate-to-service requests and would require new keys/configuration and validating SDKs ([service security](https://docs.restate.dev/services/security)). It does not itself restrict who can call port 9070.
- The pinned 1.8.0 native cap-empty schema probe succeeded: `/tmp/sfactory-registry-drain-schema-apply-envelope.json`, root receipt `/tmp/sfactory-identity-admin-8mdevoh2`. `sys_invocation_status` includes `pinned_deployment_id`; both `sys_vqueues` and `sys_vqueue_entry_status` include `deployment`. Restate's [1.7.4 release notes](https://github.com/restatedev/restate/blob/main/release-notes/v1.7.4.md) report fixing pinned-deployment visibility for queues. Actual values and ongoing invocation semantics still need a disposable positive control on the pinned binary.
- nftables documents `meta skuid` as the UID associated with the originating socket, not necessarily the current process's effective UID ([nftables socket UID documentation](https://wiki.nftables.org/wiki-nftables/index.php/Matching_packet_metainformation)). Inherited or passed descriptors, other UIDs, pre-existing connections, IPv6 and alternate interfaces must be considered. UID 2000 is also the legitimate sidecar and current administrative probe role.

## Alternatives

1. **Retire old SDKs and mediate admin over an independently restricted channel.** Under a permanent root transition marker and exclusive gate, disable socket activation and stop only the exact factory SDK4 unit after terminal/no-job and known-invocation checks; keep its deployment record and durable data. Root-owned fixed service definitions and permanent no-restart evidence must prevent automatic/manual factory restart. Apply equivalent treatment to earlier ungated SDKs if Restate can still dispatch to them. Then use the fixed SDK5 with gate-aware journal handlers. Admin 9070 still needs an enforced exclusive trusted role: stopping SDK4 alone does not prevent a UID2000 process from changing registrations or Restate invoking other ungated endpoints. New ingress must be fenced independently before the drain snapshot; queued or unpinned invocations require exact reconciliation. The temporary loss of old invocation availability is deliberate and must not be called a successful drain.
2. **Private-net output policy, constrained by originating socket UID.** In the existing task-specific private namespace only, a root-owned nftables table could deny untrusted UID 2000 to 9070 and ungated SDK ports while leaving UID 2004 Restate-to-SDK traffic and 8080/55432 available. A separately sandboxed root-owned fixed admin broker would make only preauthorized registration/queries. This requires CAP_NET_ADMIN in the correct namespace, current-ruleset inventory, safe composition with existing chains, exact table ownership, and proof for pre-established connections, descriptor passing, IPv4/IPv6, service user namespaces and restart persistence. Rules must not block Restate's UID 2004 calls to SDK4 while draining, and root-owned broker must not expose arbitrary SQL or registration. UID-based blocking does not resist a compromised trusted root, UID 2004 or an already-authorized socket passed across identities. It impacts current UID2000 inspection/registration probes and cannot be adopted without replacing them.
3. **Restate Unix admin socket with root proxy.** Potentially cleaner fixed socket permissions and peer authentication, but the current process uses `--listen-mode tcp`; changing it requires a reviewed restart of the factory's Restate service, compatibility checks and a root-managed proxy/registration path. It does not stop direct calls to old SDK listeners. No evidence yet that the exact 1.8.0 binary's Unix configuration and permission handling meet this protocol. Preserve the existing service and database until separately proven.
4. **Only the current lock, marker and SQL.** Reject: SDK4 and its older peers lack the new gate and UID2000 can access admin and direct endpoints. Snapshot counts may change after observation; a software lock observed only by new code cannot fence old code.

## Recommendation and gates

Use a disposable private-network canary to compare option 2 with a stopped-and-restart-fenced old SDK. A rule must be scoped to one newly created namespace/table and three fixed synthetic ports; do not touch this live namespace during the canary. Verify UID2000 cannot open or continue an already-established protected connection, UID2004 can reach the SDK endpoint and both roles preserve separately scoped benign traffic. Test socket transfer, IPv4/IPv6, existing rules, namespace loss and reboot; keep root-owned broker/probe to fixed operations, no arbitrary target or credentials. Before any live policy proposal, inventory actual connections and every existing admin client in the private namespace and establish safe retained-old-work behavior. If reliable enforcement needs a new identity or privileged permanent network service, treat that as a reviewed provisioning prerequisite.

On a separately reviewed transition, fsync intent before any rule or unit action, pin boot ID, namespace inode, existing ruleset digest, exact SDK unit/binary/process and immutable deployment IDs, and hold the root EX gate throughout. Establish and continuously verify ingress fencing; enumerate all old deployments and pending/unpinned invocation and queue records; require a falsifiable positive control; capture all prior history before changes. Record start intent before the single SDK5 registration, preserve unknown on timeout, bind the actual server-minted ID to the exact plan, verify manager/unit and SDK5 process attestation, replay all prior histories and only then publish completion and remove the pending marker. Recheck fence and identities immediately before release. No inference, new claim, promotion, or old-generation reset follows merely from registration.

Rollback must be narrowly scoped to the exact fixture/table/unit and only after confirming no dependent request or late operation remains. Restore the prior ruleset by removing only the task-created table after exact identity comparison; never flush shared chains, delete databases, or restart shared services. If ownership or effects are ambiguous, keep the transition closed and preserve the network/resource receipts rather than claiming rollback. A live migration cannot silently restore an ungated SDK after successful new admission.
