# Durable runtime research: registry ingress fence

Research date: 2026-10-30. Scope: the installed private factory journal and its retained histories, not the separate Stapled deployment. No host policy or service was changed.

## Material facts

1. The factory Restate is launched with `--listen-mode tcp`, loopback binding and a private systemd network namespace; the SDK and the registration helper run as UID 2000. The helper sends a registration POST to port 9070, while the SDK needs ingress port 8080 and PostgreSQL 55432. A blanket UID 2000 network denial would break required paths. [Installer source](../../../../../clean-room/deployment/nuc_private_runtime_install.py) lines 34, 112–116, 275 and 310.
2. The root registry admission lock and permanent transition marker only fence callers that actually take that lock. The transition's completion logic also requires recorded registration and replay bindings, but neither an old SDK that lacks the gate nor direct Restate admin traffic is fenced merely by that marker. [Gate source](../../../../../clean-room/deployment/nuc_registry_transition_gate.py) lines 35–60 and 165–205; [brief](brief.md).
3. Restate documents its self-hosted admin interface as having no application-level authentication and requiring network controls; its ingress is separately exposed and is intended to have an authenticated gateway. Request identity authenticates Restate-to-SDK calls, not admin callers. [Server security](https://docs.restate.dev/server/security); [service security](https://docs.restate.dev/services/security). These are vendor documentation, not proof that the installed binary is configured with either control.
4. A native read-only schema probe on the installed binary found `pinned_deployment_id` on `sys_invocation_status` and deployment fields on both queue tables. This establishes columns, not their values or a complete drain predicate. [Probe source](../../../../../clean-room/deployment/nuc_registry_drain_schema_probe.py) lines 4–18 and 32–33; actual receipt `/tmp/sfactory-registry-drain-schema-apply-envelope.json`. Restate's [1.7.4 release notes](https://github.com/restatedev/restate/blob/main/release-notes/v1.7.4.md) describe fixing deployment attribution for queued and restart-as-new work. The installed executable reports 1.8.0, but its exact upstream source commit and inclusion of that fix have not been independently established; require a pinned-binary behavioral control rather than assuming the release note applies.
5. A read-only `private-restate --help` on 2026-10-30 confirms this binary accepts `--listen-mode` values `unix`, `tcp`, and `all`. Restate's [1.6.0 release notes](https://github.com/restatedev/restate/blob/main/release-notes/v1.6.0.md) describe Unix sockets for admin, ingress and fabric, plus service-specific overrides. They do not establish exact socket ownership/modes, compatibility of current clients, or a safe live restart for this build. Unix admin alone also does not fence the old SDK HTTP endpoints.
6. A prior separately scoped disposable finalization fixture exercised exact replay, changed-payload rejection, SQL reexport and replay after restarting its own SDK and Restate. It did not exercise every retained live catalog, a live ingress fence, or the production namespace. [Fixture evidence](../../verification/2026-10-30-root-finalization-disposable.md). Do not infer real-journal drain from it.

## Options and proof gaps

**Retire ungated SDK listeners plus root-mediated admin:** a fixed root supervisor can close the exact socket/unit admission and prevent restart, while retaining the Restate deployment and durable history. This must cover every old SDK endpoint still reachable by Restate or local peers, not only the newest one. A pending invocation pinned to a retired deployment may remain unavailable: preserve it and report the condition, rather than treating an empty or inaccessible endpoint as a completed drain. The admin interface remains a separate authority and needs an exclusive fixed root-owned channel or network fence. Stop/disable alone cannot cancel an already accepted request or a late queued activation.

**Private-namespace nftables policy with fixed admin broker:** may preserve Restate UID 2004 to SDK traffic and UID 2000 to ingress/database while denying UID 2000 direct admin and ungated SDK destinations. `meta skuid` identifies socket ownership, not necessarily the current writer; inherited or passed descriptors therefore need explicit tests. Rule ordering, default policy, established flows, IPv4/IPv6 and alternate interfaces, UID namespace semantics and namespace replacement must be proven on this kernel. A root broker must expose fixed preauthorized operations, not arbitrary admin HTTP or SQL. Any rule allowing established connections before the deny can defeat the fence; do not infer existing-flow behavior from new-connect failures. The root/daemon and UID 2004 remain trusted within this proposal.

**Unix-only admin with root proxy:** potentially stronger path access control but requires testing this exact binary's per-service settings, socket mode and peer credential semantics, and replacing current TCP admin clients. If only global `listen-mode=unix` is available, existing TCP ingress/fabric clients also change. The current Restate process and durable database must not be restarted just to test this. An admin socket does not close existing old SDK endpoints or outstanding work; endpoint retirement and active-connection accounting are still mandatory.

**Gate plus SQL counts alone:** insufficient. Counts are observations, not admission closure. A newly submitted request, direct SDK request, or existing connection can race the query. Queue and invocation metadata may be null or pinned differently; classify all relevant nonterminal and unpinned entries and reconcile them without invoking an effect twice. Completed-history retention and exact deployment IDs must remain intact. If an in-flight mutation cannot be reconciled, keep transition closed and the original result unknown.

## Minimum disposable falsification sequence

Use a newly created isolated namespace, disposable Restate with the exact pinned binary and a fresh state directory, plus fixed synthetic SDKs and no credentials. First establish two distinct real deployment IDs, a controlled in-flight invocation, queued work, an unpinned request, and retained completed history; verify their actual table rows and change/restart behavior. Then install a scoped deny and prove, for the exact kernel/ruleset, refusal of new and already-established UID 2000 admin/old-SDK traffic, descriptor inheritance/transfer, IPv4 and IPv6, while UID 2004 reaches the intended SDK and benign 8080/55432 paths remain available. Test a late connection and namespace/unit loss during observation. Separately exercise Unix admin and all affected clients without assuming socket permissions. Any unexpected successful protected request, unreadable queue classification, late activation, or unknown cleanup fails the candidate; record exact resource ownership and preserve ambiguous state.

For a real transition, pin boot and namespace identity, existing ruleset and process/unit/socket identities; fsync a permanent intent while holding the root exclusive gate; enforce and recheck the independent ingress/admin fence before measuring work. Preserve and classify pinned, unpinned, queued and in-flight work, not just a count. Only after exact quiescence or explicitly retained unresolved cases may a single non-force registration be attempted, with its server-minted ID and prior history replay bound to the plan. Recheck identities and fence immediately before any release. Unknown registration, effect or rollback must retain the closed marker; do not silently re-register, reset state or restore an ungated listener.
